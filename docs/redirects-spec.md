# 仕様メモ：301 リダイレクトの管理（redirects）

- 実装プロンプト：`docs/prompt/redirects.md`
- 実装完了日：2026-10-26
- 計画書の段階4-9（SEO）の7。この段階の最後の機能

## A. 概要

**目的・解決する課題**

サイトの引っ越しや URL の変更で要るリダイレクトを、運用する人が管理画面から登録できるようにした。`.htaccess` に書くリダイレクトは、書き方の誤り・前方一致の勘違い・書いた順番の勘違いで、思った動きにならないことが多い。登録のときにそうした誤りを止め、どれが当たるかを画面で試せるようにした。

**影響範囲**

| 範囲 | 内容 |
|---|---|
| フレームワーク | テーブル `redirects` とモデル `Redirect`、`RedirectResolver`（当て方・キャッシュ・当たった回数）、`RedirectChecker`（登録のときの確かめ）、ミドルウェア `ApplyRedirects`、画面 `RedirectController` と `neobit::admin.redirects.index`・`redirects.js`、設定 `seo.redirects` |
| 見本のサイト | ルート・メニュー（「運用」の「リダイレクト」）、`vite.config.js` に `redirects.js`、`bootstrap/app.php` にミドルウェア、`public/.htaccess` から末尾の「/」を外す決まりを消した、モデルの短い名前と操作ログの対象に `redirect`、`config/neobit.php` で `redirects` を `true` |
| DB | `redirects` テーブルを足した |
| サーバー | `php artisan migrate` と、`public/.htaccess` の差し替えが要る |

## B. 実装仕様

**テーブル**（`redirects`）

| 列 | 中身 |
|---|---|
| `old_url` | 古い URL のパス（500文字まで、一意）。照合順序 `utf8mb4_bin` で、大文字と小文字・末尾の「/」の有無を別物にする |
| `new_url` | 新しい URL（1000文字まで）。`/` から始まるパスか `http(s)://` の外の URL |
| `status_code` | 301 か 302 |
| `enabled` | 有効か |
| `hits`・`last_hit_at` | 当たった回数と最後に当たった日時（画面では HIT回数・最終HIT日）。更新日時は変えずに増やす |

**当て方**（`ApplyRedirects` → `RedirectResolver::find()`）

1. GET と HEAD だけ。設定の `seo.redirects` が `true` のときだけ登録を見る
2. パスの `%` の符号を戻し（日本語のまま）、完全に一致する古い URL を探す
3. 無ければ、末尾が `*` の古い URL のうち、`*` の前で始まるものを、`*` の前が長い順に探す
4. 当たったら当たった回数を増やし、新しい URL へ移す。新しい URL の末尾が `*` なら当たった残りを引き継ぎ、新しい URL に `?` が無ければ来た `?` の後ろを付け足す。日本語は `%` の符号にする。サイトの中のパスは自分で絶対の URL にする（`redirect()->to()` が末尾の「/」を外すため）
5. 当たらず、パスの末尾が「/」（`/` だけは除く）なら、「/」を外した URL へ 301

- 有効な移し方の一覧はキャッシュ（`neobit-redirects`）に置き、`Redirect` の保存と削除のイベントで作り直す。テーブルが無いときは登録が無いものとして動く。

**登録のときの確かめ**（`RedirectChecker::errors()`。項目ごとに最初のエラーだけ）

| 順 | 確かめること | エラーの文（例） |
|---|---|---|
| 1 | 古い URL の形（`/` から始まる・`?`・`#`・空白なし） | 古いURLは、/ から始めてください。? と # は書けません。 |
| 1 | `*` は末尾に1つだけ | * は、末尾に1つだけ書けます。 |
| 1 | 新しい URL の形 | 新しいURLは、/ から始まるサイトの中のパスか、http(s):// から始まるURLにしてください。 |
| 1 | 古い URL に `*` が無いのに新しい URL に `*` | 古いURLに * が無いときは、新しいURLに * を書けません。 |
| 2 | 二重の登録 | この古いURLは、もう登録されています。 |
| 3 | 自分へのリダイレクト | 古いURLと新しいURLが同じです。 |
| 4 | 今ある引数の無い画面との重なり | この古いURLは、今ある画面（/contact）と重なります。／（`*`）…を巻き込みます。 |
| 5 | 移した先がまた自分の `*` に当たる | 移した先が、また /blog/* に当たり、くり返しになります。 |
| 5 | 輪（A → B → A） | 移した先が、ほかのリダイレクト（/b → /c）を通ってこの古いURLに戻り、くり返しになります。 |
| 5 | つながり（A → B → C） | 移した先の /a は、ほかのリダイレクト（/a → /news）に当たります。/news へ直接移すようにしてください。 |
| 5 | ほかの移した先が、この古い URL | この古いURLは、ほかのリダイレクト（/d → /e）の移した先です。そちらの新しいURLを先に直してください。 |
| 6 | 新しい URL が開けない（ルートにも public の下のファイルにも当たらない。`*` で引き継ぐものは確かめない） | 新しいURLの /No_Such は、サイトの中で開ける画面がありません。 |

- 4〜6 は、新しい URL がサイトの中のパスのときだけ。無効にした登録も、比べる相手に含める（有効に戻したときに輪にならないように）。

**画面**（`RedirectController`。ルートは案件が書き、名前の頭から組のほかの名前を作る）

- 一覧の画面：「URLを試す」の欄、古い URL での検索、並び順（古いURLの順・HIT回数の多い順・最終HIT日の古い順・登録の新しい順）、CSV のボタン、一覧、50件ずつのページ送り。別の編集の画面は持たない。
- 一覧：いちばん上が追加の行（入力欄と「追加」）。ほかの行は文字で、「編集」「削除」がある。「編集」を押すとその行だけが入力欄になり、「更新」「キャンセル」に変わる。編集中は、ほかの行の「編集」「削除」と、追加の行の入力欄と「追加」をまるごと使えなくする（`redirects.js`）。追加の行に入れかけた文字は残す。「キャンセル」は開いたときの値に戻す。削除は確認の窓から。
- 列の幅は、古いURL・新しいURLが12分の3、種類・有効・HIT回数が12分の1、ボタンの欄が10rem（「更新」「キャンセル」が並ぶ幅）、最終HIT日が残りの全部。
- 行ごとに1つのフォームにする（Bootstrap のグリッドの行）。表の行の中にはフォームを置けず、エラーの欄を赤くする範囲（`global.js`）もフォームの中に収めたいため。
- 入力エラーのときは、送った行（`editing_id` で見分ける。無ければ追加の行）だけに、入れた値とエラーを出し、その行を開いた状態で出す。
- 保存と削除の後は、直前に見ていた一覧（ページ・検索・並び順）に戻る。
- 「URLを試す」：パスか URL を入れると、当たるリダイレクト（完全一致かワイルドカードか）と移る先、または「末尾の / を外して … へ移ります。」「リダイレクトしません。サイトの画面が開きます。」「リダイレクトしません。開ける画面がありません（404）。」。
- `seo.redirects` が `false` なら、上に「設定（seo.redirects）で無効化されているので、登録しても機能しません。」。
- 追加と編集に確認画面は挟まない。保存の文は「リダイレクトを登録しました。」「リダイレクトを更新しました。」「「…」のリダイレクトを削除しました。」。

**CSV**

- 列は「古いURL・新しいURL・種類・有効（有効・無効）」。書き出しは古い URL の順。
- 取り込みは共通の取り込みの画面を、処理だけのモード（`CsvImportMode::Process`）で使う。古い URL を鍵に、ある行は更新し、無い行は追加する。変わらない行は保存しない。
- 行をまたいだ確かめ（`validateCsvRows()`）：CSV の中の古い URL の重なりと、画面と同じ `RedirectChecker::errors()`。比べる相手は、登録済みのうち CSV で上書きしないものと、CSV のほかの行。
- 完了の文は「リダイレクト：追加 N件・更新 N件を取り込みました（変更なし N件）。」。

**操作ログ**

- 追加・更新・削除は「登録・更新・削除」で、対象は `redirect`。更新では、変わった列の名前を残す（当たった回数と日時は数えない）。
- CSV は、今ある「CSVダウンロード」「CSV取り込み」。

## D. 設計判断とトレードオフ

| 判断 | 採用 | 不採用とその理由 |
|---|---|---|
| 当てる場所 | Laravel の全体のミドルウェア | `.htaccess` を書き換える：apache にファイルを書かせることになり、書き方の誤りでサイト全体が止まる |
| 一致の決まり | 完全一致と、`*` を書いたときだけの前方一致 | Apache の `Redirect` に合わせる：書かなくても前方一致になり、気付かずに下の全部を移す。正規表現：書き間違いが起きやすい |
| 当たる順番 | 完全一致 → `*` の前が長いもの。並び替えは無い | 登録の順：`.htaccess` と同じ順番の勘違いが起きる |
| 末尾の「/」 | 別物。`.htaccess` の決まりをミドルウェアへ移す | `.htaccess` のまま：末尾が「/」の古い URL がミドルウェアに届かない。サイト全体を「/」付きの形にする：URL を作る部品の差し替えが要り、全部の URL が変わる |
| 使わないサイト | 設定 `seo.redirects` で、登録を見ない | いつも見る：キャッシュの置き場所が DB なので、読むだけで毎回 DB を引く |
| キャッシュの作り直し | モデルの保存と削除のイベント | 呼ぶ側で作り直す：画面・取り込み・コマンドのどこかで忘れると、古い一覧が残る |
| CSV の取り込み | 共通の画面の処理だけのモード | 追加と更新のモード：入力と確認の流れ（FormFlow）が要る。この画面は1画面の作り |
| 編集の形 | 一覧の行の中で編集し、編集中はほかのボタンを押せなくする | 一覧と詳細・編集の画面：行き来が多く、ほかの行と見比べながら直せない |
| 画面との重なり | 引数の無い画面だけ確かめる | 引数のある画面も：`/{slug}` はほぼどの URL にも当たり、全部がエラーになる |

## E. 課題・懸念点

| 重要度 | 内容 |
|---|---|
| 中 | サーバーの `public/.htaccess` を差し替えないと、末尾が「/」の古い URL に当たらない（`check_latest.sh` が知らせる） |
| 低 | 引数のある画面（`/{slug}`・`/news/{news}`）と重なる古い URL は止めない。リダイレクトが先に当たり、その記事は開けなくなる |
| 低 | 新しい URL が引数のある画面のとき、記事が本当にあるかまでは確かめない |
| 低 | 当たるたびに DB を1回更新する。アクセスがとても多いサイトでは、回数の記録をまとめる工夫が要る |
| 低 | テストの `get()` は末尾の「/」を外して送るので、末尾が「/」の URL のテストは、カーネルに直接リクエストを渡して書いた |

## F. セキュリティ・権限・データ整合性の注意

- 画面を開けるのは管理者だけ（`acl.manager`）。
- 新しい URL は `/` から始まるパスか `http(s)://` だけを受け付ける（`javascript:` や `//` から始まる URL は断る）。外の URL へ移せるので、登録できる人を管理者に絞っている。
- 古い URL の一意は、照合順序 `utf8mb4_bin` の一意の索引でも守る。
- 当たった回数は、更新日時を変えずに増やす（取り込みの変更の見分けや、操作ログに影響させない）。

## G. テスト状況

**実施済み**（`tests/Feature/RedirectTest.php`、11件）

- 完全一致で移し、`?` の後ろを引き継ぐ（新しい URL に `?` があれば引き継がない）。当たった回数と日時が増え、更新日時は変わらない
- 完全一致が先、`*` の前が長いものが先。`/blog` には `/blog/*` が当たらない
- 末尾の「/」は別物。登録の無い末尾が「/」の URL は外して 301。設定で止めると外すだけ
- POST と無効にした登録には当てない
- 日本語の URL は `%` の符号でも当たり、日本語の新しい URL は `%` の符号で返す
- 画面からの追加・試す・行の中での編集（見ていた一覧に戻る・入力エラーでその行が開く）・削除と、操作ログ
- 形・二重・自分・画面との重なり・巻き込み・輪・つながり・反対のつながり・開けない新しい URL を断る
- 設定で止めているときの画面の文、管理者でないスタッフは開けない
- CSV の書き出しと取り込み（追加と更新）、CSV の中の重なりとつながりで何も保存しない

全体で 460件が通る。
