# 仕様メモ：記事を持たないページの「SEO 設定」の画面（seo-settings）

- 実装プロンプト：`docs/prompt/seo-settings.md`
- 実装完了日：2026-10-26
- 計画書の段階4-9（SEO）の5

## A. 概要

**目的・解決する課題**

記事を持たないページ（トップページ・一覧・お問い合わせなど）の SEO と、サイト全体の既定を、運用する人が管理画面から変えられるようにした。今までは設定ファイルとテンプレートの `@section('title')` で決まり、変えるには開発者がファイルを直す必要があった。あわせて、Google Search Console の確認タグを `<head>` に出せるようにした。

**影響範囲**

| 範囲 | 内容 |
|---|---|
| フレームワーク | `SeoSettings`（値の読み書き・キャッシュ・操作ログ）、`SeoSettingsController` と画面 `neobit::admin.seo_settings.index`、`Seo`（優先・`site_verification`・`IMAGE_URL_PATTERN`）、`_seo_head`（確認タグ）、`SitemapController`（画面の noindex のページを外す）、操作の種類 `seo_settings_change`、設定の `seo.page_routes` |
| 見本のサイト | 管理画面のルート（`admin.seo-settings.index`・`update`）とメニュー（「運用」の「SEO設定」）、`config/neobit.php` の `page_routes`（トップページ・お知らせの一覧・お問い合わせ・メルマガの登録・会員登録） |
| DB | 変更なし（今ある `settings` テーブルに、キーで足す） |

## B. 実装仕様

**値の持ち方**（`settings` テーブル）

| キー | 値 | 空のとき |
|---|---|---|
| `seo.title_format` | 文字 | null。設定ファイルの `seo.title_format` |
| `seo.description` | 文字 | null。設定ファイルの `seo.description` |
| `seo.image` | 文字（`/` から始まるパスか `http(s)://`） | null。設定ファイルの `seo.image` |
| `seo.site_verification` | 文字（英数字・`_`・`-`） | null。タグを出さない |
| `seo.pages` | `{ルート名: {title, description, image, noindex}}` | 何も入れていないルートは持たない |

- 画面の設定は `Cache::forever('neobit-seo-settings')` に置き、保存で消す。`settings` テーブルが無いとき（マイグレーションの前）は、画面の設定が無いものとして動き、キャッシュには置かない。
- `seo.pages` のうち、今の `seo.page_routes` に無いルートの値は使わない。保存では、`page_routes` に無いルートの値を捨てる。

**値の優先**（`Seo`）

| 値 | 優先の順 |
|---|---|
| タイトル | 記事の SEO の欄 > 記事のタイトル > 画面のページのタイトル > `@section('title')`。形は画面の既定 > 設定ファイル。どれも無ければサイト名だけ |
| 説明文 | 記事の SEO の欄 > 記事の本文 > 画面のページの説明文（切り詰めない）> 画面の既定 > 設定ファイル |
| シェアの画像 | 記事の SEO の欄 > 記事の画像 > 画面のページの画像 > 画面の既定 > 設定ファイル |
| noindex | 今までの決まりに、画面のページの「検索に出さない」を足した |
| 確認タグ | `seo('site_verification')`。`_seo_head` が `<meta name="google-site-verification">` を全部のページに出す |

**画面**（`SeoSettingsController`。ルートは案件が「頭.index」（GET）「頭.update」（PATCH）で書く）

- サイト全体の既定（タイトルの形・既定の説明文・既定のシェアの画像の URL・確認タグ）と、`page_routes` の順のページごとの欄（タイトル・説明文・シェアの画像の URL・検索に出さない）。
- ページはふだん閉じた枠（`<details>`）で、ページ名をクリックすると開く。ページが増えても画面が長くならないため。閉じていても分かるよう、保存してある値があれば「設定あり」、検索に出さないにしたページは「検索に出さない」の目印を出す。入力エラーのあるページだけ開いて出す。
- ページの欄は `pages[番号][route]`・`[title]`・`[description]`・`[image]`・`[noindex]` で送る。ルート名に「.」が入るので、名前の鍵にはしない。
- 空欄の既定には、設定ファイルの値を入力欄の見本（placeholder）で出す。ページの URL は `route()` で作り、引数の要るルートでは出さない。
- `page_routes` が空なら「設定の seo.page_routes にルートを並べると、ここに出ます。」とだけ出す。
- 保存の後は「SEO設定を保存しました。」。確認画面は挟まない。

**検証**

| 項目 | 決まり | エラーの文 |
|---|---|---|
| タイトルの形 | 100文字まで。`{title}` を含む | タイトルの形には {title} を入れてください。 |
| 既定の説明文・ページの説明文 | 300文字まで | 決まりの文 |
| ページのタイトル | 60文字まで | 決まりの文 |
| 画像の URL | 255文字まで。`Seo::IMAGE_URL_PATTERN`（記事の SEO の欄と同じ） | 決まりの文 |
| 確認タグ | `<meta …content="…">` を貼ったら content の値を取り出し、英数字・`_`・`-` の100文字まで | 確認タグの形が正しくありません。 |

**操作ログ**

- 操作の種類「SEO設定の変更」（`seo_settings_change`）。補足に「変えた項目：タイトルの形・トップページ」のように、変えた項目の名前だけを残す。
- 保存の前と後を比べ、何も変わっていなければ残さない。

## C. 前提・依存

- SEO の出す部品（段階4-9の1）・記事ごとの SEO の欄（2）・自動の noindex とサイトマップ（4）
- `settings` テーブルと `Setting` モデル（アクセス制限と共用）
- 管理者だけが入れるルートのグループ（`acl.manager`）

## D. 設計判断とトレードオフ

| 判断 | 採用 | 不採用とその理由 |
|---|---|---|
| 値の置き場所 | `settings` テーブルにキーで足す | 専用のテーブル：キーと値で足り、マイグレーションが増えるだけ |
| 画面に出すページ | 専用の設定 `seo.page_routes`（ルート名 => 画面に出す名前） | `sitemap_routes` の流用：画面に出す名前が要り、サイトマップに載せるページと SEO を書きたいページは同じとは限らない |
| 画面の値と `@section('title')` | 画面の値が先 | `@section('title')` が先：運用する人が画面で入れた値が効かなくなる。`@section('title')` は開発者が置いた既定 |
| 確認タグ | タグを丸ごと貼っても受け付け、content の値だけを保存 | 値だけ：Search Console はタグの形で示すので、貼り間違いが起きやすい |
| 確認タグを出す場所 | 全部のページ | トップページだけ：全部に出しても害がなく、`_seo_head` の1か所で済む |
| ページの欄の送り方 | 番号＋hidden のルート名 | ルート名を鍵にする：ルート名の「.」が、検証の名前の区切りと重なる |
| ページの枠 | ふだん閉じ、目印で設定したページを示す | 記事の SEO の欄と同じく値があれば開く：ページが増えると画面が長くなる |
| 操作ログ | 変えた項目の名前だけ | 値も残す：説明文が長く、操作ログが読みにくくなる |

## E. 課題・懸念点

| 重要度 | 内容 |
|---|---|
| 低 | トップページのタイトルもタイトルの形に当てはまるので、「サイト名｜キャッチコピー」のような形にはできない。要るなら「トップは形に当てはめない」の選択を足す |
| 低 | 画面の設定をキャッシュに置くので、DB を直接書き換えたときは反映されない。保存は画面（`SeoSettings::save()`）を通すか、キャッシュを消す |
| 低 | 操作ログには値を残さないので、何から何に変えたかは追えない |
| 低 | 引数の要るルートを `page_routes` に書くと、画面に URL が出ない（値は効く） |

## F. セキュリティ・権限・データ整合性の注意

- 画面を開けるのは管理者だけ（`acl.manager`）。一般のスタッフは自分の情報の画面へ移す。
- 値は全部 `{{ }}` で出す。確認タグは英数字・`_`・`-` に限り、画像の URL は `/` から始まるパスか `http(s)://` に限る（`javascript:` と `//` から始まる URL を断る）。
- `page_routes` に無いルートの値は、送られても保存しない。

## G. テスト状況

**実施済み**（`tests/Feature/SeoTest.php` に6件。全部で21件）

- 画面の既定とページの値が、設定ファイルより先に効く。確認タグを丸ごと貼ると、content の値だけを出す。先に開いて置いたキャッシュが、保存で作り直される。操作ログは1件で、同じ値の保存では残さない
- 画面のページのタイトルが `@section('title')` より先に効き、記事のあるページでは記事の値のまま。引数の要るルートも画面に並ぶ
- 全部を空にすると、値は null・ページは空になり、設定ファイルの値に戻る
- 閉じたページの枠に「設定あり」の目印が出る
- 画面で検索に出さないにしたページに noindex が付き、サイトマップから外れる
- `{title}` の無いタイトルの形、`/` から始まらない画像、`//` から始まる画像、形の違う確認タグを断る。`page_routes` に無いルートの値は捨てる
- 管理者でないスタッフは開けない
