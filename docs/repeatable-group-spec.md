# 仕様メモ：繰り返しの組（repeatable-group）

- 実装プロンプト：`docs/prompt/repeatable-group.md`
- 実装完了日：2026-10-20

## A. 概要

**目的・解決する課題**

子テーブルの1行を「いくつかの項目（ファイルを含んでよい）の組」として、画面で行を増やしたり消したりしながら入力し、親と一緒に保存できるようにする。

今までは、アップロードの複数の欄（`'attach.*'`）だけが繰り返しを受け持ち、1行＝ファイル1つ（`filename`・`original_name`）に限られていた。ラベルや説明を一緒に持つ子テーブルや、ファイルの無い繰り返しの項目は、コーナーごとに検証・値の組み立て・保存・枠の増減の画面を書くことになり、写すたびに食い違いが生まれていた。

**対象範囲**

| 含む | 含まない |
|---|---|
| フレームワークの部品（`RepeatableGroup`・`RepeatableGroupDefinitions`・`_repeatable_group`・`repeatable_group.js`） | CSV の取り込み（組の列を子テーブルに書き戻す） |
| FormFlow からの呼び出し（値の組み立て・空の行の除き方・保存・削除） | 行の並べ替えの操作（ドラッグなど） |
| 組の中のファイルの欄（`UPLOAD_FILES` の `'photos.*.image'`）の受け取り・確定・削除・非公開の表示 | 今の複数の欄（`attach.*`）の作り直し |
| 見本：ニュースの写真（画像とキャプション） | ファイルの無い組の見本 |
| 利用ガイド・名前の一覧・パッケージ化の計画書（段階 4-8） | 見本の CSV の書き出しへの写真の列の追加 |

## B. 実装仕様

**定義**（コントローラー）

```php
private const REPEATABLE_GROUPS = [
    'photos' => [
        'relation' => 'photos',            // 必須。子テーブルへのHasMany
        'fields' => ['image', 'caption'],  // 必須。組の項目＝子テーブルの列
        'order' => 'display_order',        // 省略可。並び順の列
        'max' => 10,                       // 必須。行の数の上限
        'min' => 0,                        // 省略可。行の数の下限
    ],
];
private const UPLOAD_FILES = [
    'photos.*.image' => ['type' => UploadType::Image, 'width' => 1000],  // 組の中のファイルの欄。'max'は書かない
];
```

- 組の名前と項目は、英小文字・数字・「_」。書き方の誤りは、最初に読んだときに `LogicException`。
- ファイルの項目があるのに `AjaxFileUpload` を使っていなければ `LogicException`。
- `'組.*.列'` の列が、その組の `fields` に無ければ `LogicException`。

**画面から送る値**

| 名前 | 中身 |
|---|---|
| `{組}_group` | 組が送られた印（`1`）。行が1つも無いときも送る |
| `{組}_id[]` | 行の id。新しい行は空 |
| `{組}_{項目}[]` | ファイルではない項目の値 |
| `{組}_{列}[]`・`_tmp[]`・`_origin[]`・`_del[]` | ファイルの項目。アップロードの欄と同じ4本 |

**検証**（`repeatableGroupRules()`）

- 列ごとの配列は、どれも同じ要素数（`SameCountAsRule`）
- `{組}_id` は `max:上限`（`min` があれば `min:下限`）。空の行を除いた後の行の数で数える
- `{組}_id.*` は整数、ファイルの項目の4本の要素はアップロードの欄と同じ形
- 項目の要素のルール（`'photos_caption.*'`）は、コントローラーの `rules()` に書く

**業務ルール**

- 空の行：ファイルではない項目がどれも空で、ファイルの項目がどれも「今のファイルも新しいファイルも無いか、削除の印が立っている」行。検証の前に、全部の配列から同じ位置を除く。id だけの行も空とみなす（保存で消える）。
- 保存：
  - この親の行の id は更新。ほかの親の行の id、2回目に出てきた同じ id、id の無い行は追加。届かなかった行は削除
  - 並び順の列には、画面の並びの番号（0から）
  - ファイル：新しいファイルは一時ファイルを保存先へ移す。今のファイルは、送られた名前が「その行の今の値」と一致し、削除の印が無いときだけ残す。使わなくなったファイルは、保存の前後の比較で決め、トランザクションが確定した後に消す
  - 組の印が届いていない組と、CSV 取り込みでは何もしない
- 削除：親を消す前に、子テーブルの行を消し、ファイルは確定の後に消す。
- 非公開のファイル：欄の名前（`photos_image`）を前から「_」で区切り、リレーション（`photos`）と子テーブルの列（`image`）を探して、その列の行にあるファイルだけを返す（`UploadedFileController`）。

**処理フロー**（FormFlow）

1. `inputPageValues()`・`confirmPageValues()`：`repeatableGroupValues()` が、組の印のある入力からは揃え直して、無ければ子テーブルの今の行から、列ごとの配列を組み立てる
2. `validatedInput()`：`dropEmptyRepeatableRows()` で空の行を除いてから検証する
3. `saveValidated()`：本体の保存とアップロードの確定の後に `saveRepeatableGroups()`
4. `deleteData()`：本体を消す前に `deleteRepeatableGroups()`

**見本**

- テーブル `t_news_photos`（`news_id`・`image`・`image_origin`・`caption`・`display_order`）、モデル `NewsPhoto`（`image_url` のアクセサ）、`News::photos()`
- 管理画面のニュースの入力・確認・詳細に「写真」（横並び、上限10）、訪問者向けの詳細に写真とキャプション
- 写真は、ニュースのほかのファイルと同じく非公開の置き場所（`News::PRIVATE_FILE_FIELDS` に `photos_image`）

## C. 前提・依存

- FormFlow（値の組み立て・検証・保存・削除）
- AjaxFileUpload（組の中のファイルの欄の受け取り `uploadAjaxFile()`・一時ファイルの移し方 `moveTmpToFinal()`）、UploadFieldDefinitions、UploadFilePath、UploadedFileController
- 確認画面の hidden の部品 `_confirm_hidden`（1段の配列）
- 子のモデルの `$fillable` に、組の項目・`{列}_origin`・並び順の列を入れる
- 画面で `repeatable_group.js`（と、ファイルの項目があれば `ajax_upload.js`）を読み込む。`vite.config.js` の一覧に入れてある

## D. 設計判断とトレードオフ

| 判断 | 採用 | 不採用とその理由 |
|---|---|---|
| 保存の仕方 | 行の id を保って、更新・追加・削除 | 全部消して作り直す（今の `attach.*`）：行の id が毎回変わり、ほかから参照できない |
| 送る値の形 | 列ごとの配列 | 行ごとの連想配列（`photos[0][caption]`）：`_confirm_hidden` が2段の配列を持ち回れず、アップロードの欄の name の付け方とも合わない |
| 組を空にすることの伝え方 | 組の印（`{組}_group`）を送る | 配列の有無で決める：行を全部消すと配列が空になり、確認画面から先へ何も持ち回られず、「空にする」と「送っていない」を見分けられない ※プロンプトに無かった点 |
| ファイルの欄の書き方 | `UPLOAD_FILES` に `'photos.*.image'` | 組の定義の中にファイルの種類を書く：アップロードの欄の定義と受け取りの仕組みを、そのまま使えなくなる |
| ファイルの削除 | 組の部品が、自分の行の保存の前後を比べて消す | `commitUploads()` の前後の比較に混ぜる：組の保存はアップロードの確定の後なので、前後の取り方が合わない。ファイル名はランダムなので、別々に比べても消し違えない |
| 空の行を除く場所 | FormFlow の `validatedInput()` の1か所 | コントローラーやビューで除く：確認画面と保存で結果が食い違いうる |
| 行の中のアップロードの枠の× | 出さない（いくつでも足せる欄のときだけ出す） | 行の番号があれば出す（今まで）：組の行の中で×を押すと、アップロードの枠の JS が組を見つけられずに止まる |
| 非公開のファイルの照合 | 欄の名前を「_」で区切って、リレーションと列を探す | 欄の名前とリレーションの対応をモデルに書かせる：書くことが増える。コントローラーの定義は、ファイルを返すコントローラーからは引けない |
| CSV | 取り込みは次の段階。見本の CSV には写真の列を足さない | 見本の CSV に組の横展開の列を足す：ニュースの CSV は取り込みと定義を共有しているので、取り込めない列が混ざる ※書き出しは、見本の CSV ではなく `CsvColumnSet` を直接使うテストで確かめた |

## E. 課題・懸念点

| 重要度 | 内容 |
|---|---|
| 中 | CSV の取り込みは組を保存しない。取り込みで子テーブルを直したいときは、次の段階の作業が要る |
| 中 | 組の子テーブルの変更は、操作ログの「変わった列」に入らない。写真だけを直した保存は、更新の記録に変わった列が出ない |
| 中 | 行の数の上限・下限の検証のエラーの文は、Laravel の既定（「photos id の項目数は…」）で、項目名が利用者に分かりにくい |
| 低 | 非公開のファイルの照合は、欄の名前を「_」で区切って探す。組の名前と列の名前の両方に「_」があると、前から探して最初に当たったリレーションと列を使う |
| 低 | 今の複数の欄（`attach.*`）と組の部品の、2つの仕組みが並んでいる |
| 低 | 行の並べ替えの操作は無い。並びを変えるには、行を消して足し直す |

## F. セキュリティ・権限・データ整合性の注意

- ほかの親の行の id を送られても、その行は変えない（新しい行として足す）。
- 今のファイルは「その行の今の値」と一致するときだけ残す。hidden を書き換えて、ほかの行や欄のファイルを指させても残らない（消されることも無い）。
- 使わなくなったファイルは、トランザクションが確定した後に消す。保存が取り消されたときに、残る行のファイルが無くならない。
- 非公開のファイルは、その列の行にあるファイル名のときだけ返し、見てよいかは今までどおりモデルの Policy（`viewFiles`）で決める。
- 子テーブルは親より先に消す（外部キー制約を付けたテーブルでも消せるように）。
- 行の数の上限は、画面だけでなく保存のときの検証でも守る。

## G. テスト状況

**実施済み**（`tests/Feature/RepeatableGroupTest.php`、19件）

- 登録：画面の順で保存され、空の行は入らない。画像は保存先へ移り、表示名が入る
- 登録で送られた id は使わない（ほかの記事の行は変わらない）
- 更新：行の id を保ち、追加と削除ができ、並び順が直る
- 差し替えたファイルと消したファイルが、保存の後に消える
- ほかの行のファイル名を送っても、持ち主の行のファイルは残り、送った行には付かない（この確かめで、行を消した後のファイルの一覧の取り違えの不具合を見つけて直した）
- 同じ id が2回あれば、2回目は新しい行になる
- 組の印が無ければ触らない、印があって行が無ければ全部消す
- 行の数の上限
- 確認画面に、空の行を除いた行が hidden で持ち回られる
- 編集の画面で、並び順のとおりに出る
- ニュースを消すと、行とファイルが消える
- 非公開の写真が、その行のファイルのときだけ返る
- 管理画面の詳細と更新の確認画面に、行（キャプション・保存済みの画像のプレビュー・行の id の hidden）が出る
- 訪問者向けの詳細に、写真とキャプションが出る（画像の無い行はキャプションだけ）。一般公開の記事の写真は、ログインしていなくても見られる
- CSV の組の横展開（`CsvColumnSet`）で、行が「キャプション:1」「画像:1」…の列に出る
- 定義の読み方と、書き方の誤り（`max` が無い、組に無いファイルの欄、`AjaxFileUpload` が無い）

全体で 388件が通る。
