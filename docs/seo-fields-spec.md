# 仕様メモ：記事ごとの SEO の欄（seo-fields）

- 実装プロンプト：`docs/prompt/seo-fields.md`
- 実装完了日：2026-10-25
- 計画書の段階4-9（SEO）の2

## A. 概要

**目的・解決する課題**

運用する人が、記事ごとに SEO のタイトル・説明文・シェアの画像・検索に出さない（noindex）を、各コーナーの登録・編集の画面で決められるようにした。値はフレームワークの共通のテーブルに持つので、どのコーナーでも、コーナーのテーブルに列を足さずに、部品を1行置くだけで使える。

**影響範囲**

| 範囲 | 内容 |
|---|---|
| フレームワーク | 共通のテーブル `seo_metas`、モデル `SeoMeta`、トレイト `HasSeoMeta`（モデル）・`SeoFields`（コントローラー）、部品 `neobit::_seo_fields`。`Seo` が SEO の欄の値を優先し、`robots` を足した。FormFlow が値の組み立て・保存・削除で SEO の欄を呼ぶ |
| 見本のサイト | ニュースと固定ページの登録・編集の画面に、SEO の欄を足した |
| CSV・操作ログ | SEO の欄は CSV に含めない。変更は操作ログの「変わった列」に入らない |

## B. 実装仕様

**テーブル**（`seo_metas`。フレームワークのマイグレーション）

| 列 | 型 | 中身 |
|---|---|---|
| `seoable_type`・`seoable_id` | 文字（50）・数 | どのモデルの何番か。モデルの種類は短い名前（`enforceMorphMap()`）。2つで一意 |
| `title` | 文字（60）・NULL 可 | SEO のタイトル |
| `description` | 文字（300）・NULL 可 | 説明文 |
| `image` | 文字（255）・NULL 可 | シェアの画像の URL |
| `noindex` | 真偽値 | 検索に出さない |

**検証**（`SeoFields::seoRules()`）

- `seo_title`：60文字まで。`seo_description`：300文字まで。
- `seo_image`：255文字まで。`/` から始まり、次が `/` でないサイトの中のパスか、`http://`・`https://` から始まる URL。空白は不可。`javascript:` やプロトコルを省いた `//` は断る。
- `seo_noindex`：`0` か `1`。

**値の組み立てと保存**（`SeoFields`・FormFlow）

- 画面へ渡す `$input`：入力し直していた値（確認画面から戻ったとき・入力エラーのとき）に SEO の欄があればそれを、無ければ記事の今の SEO の欄を使う（`FormFlow::inputPageValues()` が `seoFieldValues()` を呼ぶ）。
- 保存：本体の保存の後に、同じトランザクションの中で `saveSeoFields()` を呼ぶ。SEO の欄の値が届いていなければ（部品を置いていない画面）、触らない。全部空なら行を消し、そうでなければ1行を作るか書き換える。CSV 取り込みでは保存しない。
- 削除：`deleteData()` で、本体を消す前に `deleteSeoFields()` で行を消す。

**値の決め方**（`Seo`）

- タイトル・説明文・画像は、SEO の欄、記事（`SeoSubject`）、サイトの既定の順。SEO の欄の説明文は、そのまま使う（本文から作るときの切り詰めはしない）。
- `robots`：SEO の欄で検索に出さないにしていれば `noindex`、そうでなければ空。`neobit::_seo_head` は、空でなければ `<meta name="robots" content="noindex">` を出す。

**画面**（`neobit::_seo_fields`）

- 入力の画面：`<details>` の「SEOの設定（空欄なら自動）」の枠。値かエラーがあれば開いた状態。欄は SEO のタイトル・説明文・シェアの画像の URL・検索に出さない（hidden の 0 とチェックボックスの 1）。空欄のときに使う値を、欄の薄い字（placeholder）で案内する。
- 確認・詳細の画面：入れた値だけを並べる。全部空なら「（自動）」。

**見本のサイト**

- `News`・`Page` に `HasSeoMeta`。`Admin\NewsController`・`Admin\PageController` に `SeoFields` と `seoRules()`。
- `admin/news/_fields`・`admin/pages/_fields` の末尾に `@include('neobit::_seo_fields', ...)`。

## C. 前提・依存

- SEO の出す部品（段階4-9の1。`docs/seo-head-spec.md`）
- FormFlow の値の組み立て・保存・削除の流れ
- モデルの短い名前の登録（`Relation::enforceMorphMap()`）。登録の無いモデルでは、`seo_metas` の行を作れない

## D. 設計判断とトレードオフ

| 判断 | 採用 | 不採用とその理由 |
|---|---|---|
| 値の置き場所 | 共通のテーブル（ポリモーフィック） | コーナーのテーブルに列を足す：コーナーを作るたびにマイグレーションと保存の処理が要り、名前も食い違いやすい |
| シェアの画像 | URL の文字の欄（B） | アップロード：アップロードの部品が記事のテーブルの列に保存する作りで、広げる手間が大きい。記事の中の画像から選ぶ：候補を集める処理がコーナーごとに要る |
| 全部空のとき | 行を消す | 空の行を残す：自動の値と見分けにくい |
| 部品を置いていない画面からの保存 | SEO の欄に触らない | 空として保存する：ほかの画面から保存したときに、入れた値が消える |
| 入力の枠 | `<details>`（JavaScript が要らない） | Bootstrap の折りたたみ：JavaScript が要り、確認画面から戻ったときの開け閉めの扱いが増える |

## E. 課題・懸念点

| 重要度 | 内容 |
|---|---|
| 低 | シェアの画像の URL に入れた画像を後で消すと、シェアの画像が出なくなる。URL の先にファイルがあるかは確かめていない |
| 低 | SEO の欄の変更は、操作ログの「変わった列」に入らない（子テーブルと同じ） |

## F. セキュリティ・権限・データ整合性の注意

- 画像の URL は、サイトの中のパスか `http(s)://` だけを受け付ける。`javascript:` などは断る。値は Blade の `{{ }}` で出すので、エスケープされる。
- 入力できるのは、そのコーナーの登録・編集ができるスタッフだけ（コーナーのルートと権限のまま）。
- 記事を消すと、SEO の行も同じトランザクションの中で消す。

## G. テスト状況

**実施済み**（`tests/Feature/SeoTest.php`、全部で10件）

- 編集の画面に閉じた「SEOの設定」の枠が出る。値を入れて保存すると、確認画面に出て、訪問者の側のタイトル・説明文・画像・`robots` が SEO の欄の値になる。値があると、編集の画面で枠が開いた状態で出る
- SEO の欄を全部空にして保存すると、行が消え、自動の値に戻る
- 画像の URL に、`/` から始まらないパス・`javascript:`・`//` から始まる URL を入れると断る
- ニュースを消すと、SEO の行も消える

全体で 430件が通る。
