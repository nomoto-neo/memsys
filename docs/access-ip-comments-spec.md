# 仕様メモ：アクセス制限の IP アドレスのコメント（access-ip-comments）

- 実装プロンプト：`docs/prompt/access-ip-comments.md`
- 実装完了日：2026-10-30

## A. 概要

**目的・解決する課題**

管理画面の「アクセス制限」の IP アドレスの欄に、`#` でコメントを書けるようにした。どの IP アドレスが誰のものかを残せず、一時的に外して確かめた後に元へ戻すのも手間だったため。

あわせて、画面の項目の名前を、チェックを入れると何が起きるかがそのまま分かる名前にし、上から順に読める1つの枠に並べ直した。管理画面の許す IP アドレスはサイトの制限でも通す（2026-10-29）ので、その働きを欄の名前に表した。

**影響範囲**

| 範囲 | 内容 |
|---|---|
| フレームワーク | `AccessRestriction`（書き方の読み取り・入力した文の保存・操作ログ・締め出さないための知らせ）、`AccessRestrictionController`、アクセス制限の画面、`app:access-denied-off` の文言 |
| データ | settings テーブルに、入力した文のキーを2つ足した（`access.site_allowed_ips_text`・`access.admin_allowed_ips_text`）。マイグレーションは要らない |
| 変わらないもの | 判断（`Gate`）と入口の見張りの状態のファイル（IP アドレスの一覧だけ）、`.env` の `SITE_ALLOWED_IPS`・`ADMIN_ALLOWED_IPS`（カンマ区切りのまま）、IP ブロックの画面 |

## B. 実装仕様

**書き方**（`AccessRestriction::parseList()`）

- 1行に1つ。改行は `\r\n`・`\r`・`\n` のどれでもよい
- 最初の `#` から後ろはコメント。IP アドレスとの間の空白は、あってもなくてもよい
- `#` の前が空の行（行の頭が `#` の行と、空の行）は読み飛ばす
- カンマでは区切らない。`203.0.113.10, 203.0.113.11` は、1つの正しくない形として知らせる
- 正しくない形の行は、保存させずに知らせる。知らせにはコメントも括弧で付ける（`203.0.113（事務所）`）
- 同じ IP アドレスは1つにまとめる。コメントは、IP アドレスをキーにして返す（操作ログで使う）

**保存**（`AccessRestriction::save(bool, string, bool, string)`）

- 入力した文を受け取り、その文と、そこから作った IP アドレスの一覧の両方を保存する
- 画面には入力した文をそのまま出す。前後の空白は、Laravel が送られたときに外す（`TrimStrings`）
- 入力した文がまだ無い設定（前の版で保存したもの）は、一覧を1行1つにして出す
- 非常口（`turnOff()`）は、入力した文をそのまま残して、制限だけを外す

**画面**（上から順に、1つの枠）

| 項目 | 中身（フォームの名前） |
|---|---|
| メンテナンス画面を表示する | サイトの制限（`site_restricted`） |
| メンテナンス中も訪問者画面を閲覧できるIPアドレス | サイトの許す IP アドレス（`site_ips`）。欄の名前の下、入力欄の上に「（IPアドレスは1行に1つ。# から後ろはコメントです。行の頭に # を付けると、その行は使いません。）」。`.env` の分は入力欄の下に出す |
| 常にサイト全体を閲覧できるIPアドレス | 管理画面の許す IP アドレス（`admin_ips`）。欄の名前の下、入力欄の上に「（メンテナンス中でも訪問者画面を閲覧でき、管理画面の存在を隠していても管理画面に入れます。）」 |
| 管理画面の存在を隠す | 管理画面の制限（`admin_restricted`）。下に「管理画面の存在を隠しても、「常にサイト全体を閲覧できるIPアドレス」の人は管理画面に入れます。」 |

**操作ログ**

```
メンテナンス画面：表示する
メンテナンス中も訪問者画面を閲覧できるIPアドレス：203.0.113.10（事務所） 198.51.100.0/24（支社）
常にサイト全体を閲覧できるIPアドレス：192.0.2.50
管理画面の存在：隠す
```

行の頭の `#` で外した行は並べない。

## C. 前提・依存

- アクセス制限（利用ガイドの24章）と、管理画面の許す IP アドレスをサイトの制限でも通す決まり（2026-10-29）
- settings テーブル（`Neobit\Core\Models\Setting`）

## D. 設計判断とトレードオフ

| 判断 | 採用 | 不採用とその理由 |
|---|---|---|
| コメントの保存 | 入力した文をそのまま保存し、一覧は別に保存する | 1件ずつ IP アドレスとコメントの組で保存する：空の行や並び順、外した行のコメントを残せない |
| カンマ区切り | 画面の入力では廃止 | 残す：コメントの中のカンマを区切りと取り違える |
| 判断に使う一覧 | 今までのキーのまま保存する | 毎回の判断で文を読み直す：毎回のアクセスで、文を読み取る手間が増える |
| 項目の名前 | チェックを入れると何が起きるかを、そのまま名前にする（「メンテナンス画面を表示する」「管理画面の存在を隠す」） | 「サイトの制限」「管理画面の制限」：何が起きるかが分からず、「チェックを入れると〜」の説明が要る |
| 並び | 2つの IP アドレスの欄を続け、その後に管理画面のチェック | サイトと管理画面の2つの枠：「常にサイト全体を閲覧できる」が両方に効くことが伝わりにくい |
| 「サイト」の欄の名前 | 「メンテナンス中も訪問者画面を閲覧できる」 | 「サイトを閲覧できる」：管理画面も含むように読め、「常にサイト全体」との違いが分からない |

## E. 課題・懸念点

| 重要度 | 内容 |
|---|---|
| 低 | 入力した文は5000文字まで（今までと同じ）。コメントを長く書くと、早く届く |
| 低 | 画面の名前を変えたので、運用する人への説明（マニュアルなど）があれば合わせる |

## F. セキュリティ・権限・データ整合性の注意

- コメントは操作ログに残る。個人の名前などを書くときは、操作ログを見られる人に見えることを踏まえる
- 入口の見張りの状態のファイルには、コメントを書き出さない

## G. テスト状況

**実施済み**（`tests/Feature/AccessRestrictionTest.php`）

- コメント（空白あり・なし）と、行の頭の `#` で外した行。判断に使う一覧には、使う行だけが入る
- 入力した文が、コメントも並び順もそのまま画面に出る
- 操作ログに、使う IP アドレスとコメントが並び、外した行は並ばない
- カンマで区切った2つは、正しくない形として知らせる
- 前の版で保存した設定は、一覧を1行1つの文にして出す
- 非常口のコマンドは、コメントも残して制限だけを外す
- 呼び方を変えた `save()` を使うテスト（`GateStateTest`・`IpBlockTest`）も通る
- 全体で 517件（成功 516件、飛ばし 1件）

**開発サーバーで確かめたこと**（2026-10-30）

- 今の設定が、1行1つで出る
- コメントを書いて保存でき、開き直してもコメントが残る
- 行の頭に `#` を付けた行の IP アドレスは使われない
- 操作ログに、`203.0.113.10（事務所）` の形で残る
