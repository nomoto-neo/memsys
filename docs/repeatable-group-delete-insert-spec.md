# 仕様メモ：繰り返しの組の作り直す保存（repeatable-group-delete-insert）

- 実装プロンプト：`docs/prompt/repeatable-group-delete-insert.md`
- 実装完了日：2026-10-21

> **名前の変更（2026-10-21 追記）**
> PHP の側の名前を変えた。`REPEATABLE_GROUPS` → `CHILD_TABLES`、`RepeatableGroup` → `ChildTables`、`RepeatableGroupDefinitions` → `ChildTableDefinitions`、`repeatableGroupRules()` → `childTableRules()`、テストは `ChildTablesTest`。画面の部品（`_repeatable_group` など）の名前は変わらない。下の文中の古い名前は、この追記の前の名前を指す。詳しくは `docs/child-tables-rename-spec.md`。

## A. 概要

**目的・解決する課題**

繰り返しの組（`RepeatableGroup`。`docs/repeatable-group-spec.md`）に、保存のたびに子テーブルの行を全部消して、画面の順に入れ直す保存の仕方（`'delete_insert' => true`）を足した。行の id をほかから参照せず、並び順の列も持ちたくない子テーブルを、簡単な形で書けるようにするため。

今の、行の id を保つ保存では、並び順の列が無いと、途中の空いた行に入れたファイルが新しい大きい id で足され、次に開いたときに末尾へ回る。作り直す保存なら、id の順が画面の順になるので、並び順の列が要らない。

見本は、ニュースの添付ファイル。並び順の列（`t_news_attachments.seq`）も消した。

**影響範囲**

| 範囲 | 内容 |
|---|---|
| フレームワーク | 組の定義に `delete_insert` を足し、保存の仕方を選べるようにした。省けば今までどおり |
| 見本のサイト | 添付ファイルの組を作り直す保存にし、並び順の列を消した。写真の組は今のまま |
| 画面・送る値 | 変わらない |

## B. 実装仕様

**定義**（`REPEATABLE_GROUPS`）

```php
'attach' => [
    'relation' => 'attach',
    'fields' => ['file'],
    'delete_insert' => true,   // 省けば false
    'max' => 5,
],
```

- `'delete_insert'` が true・false でなければ `LogicException`（「…の'delete_insert'は、trueかfalseで書いてください。」）。
- 定義の形（`RepeatableGroupDefinitions::of()`）に `delete_insert`（bool）を足した。
- `'order'` と一緒に書いてもよい。書けば、入れ直す行に画面の並びの番号を入れる。

**保存**（`RepeatableGroup::saveRepeatableGroup()`）

- 画面の順に、どの行も新しく入れ、最後に入れ直す前の行を全部消す（届かなかった行を消す処理と同じ1本の削除で、入れ直す前の行がすべて当たる）。
- 今の行のファイルを残すかどうかは、今までと同じく、送られた id がこの親の行で、ファイル名がその行の今の値と一致するときだけ残す。同じ id が2回出てきたら、2回目は今の行として扱わない。このため、どちらの保存の仕方でも、使った id を別に覚えるようにした（作り直す保存では、入れた行の id が新しい id になるため）。
- 使わなくなったファイルは、保存の前後のファイル名を比べて、トランザクションが確定した後に消す。入れ直した行のファイルは、前後の両方にあるので消えない。

**見本のサイト**

- `Admin\NewsController::REPEATABLE_GROUPS` の添付ファイルの組を `'delete_insert' => true` にし、`'order'` を外した。
- `News::attach()` は id の順に並べる。`NewsAttachment` の `$fillable`・`$casts` から `seq` を外した。
- マイグレーション `2026_10_21_300000_drop_seq_on_t_news_attachments_table.php`：`seq` があれば消す。`down()` は列を戻し、記事ごとに id の順で番号を入れる。

## C. 前提・依存

- 繰り返しの組の部品（`RepeatableGroup`・`RepeatableGroupDefinitions`）と、FormFlow の保存の流れ
- 添付ファイルの組（`docs/repeatable-group-attach-spec.md`）と、並び順の列の名前を `seq` に揃えた作業
- `2026_10_21_300000` のマイグレーションは、`seq` を足した・名前を変えたマイグレーション（`2026_10_21_000000`・`2026_10_21_200000`）の後に流れる

## D. 設計判断とトレードオフ

| 判断 | 採用 | 不採用とその理由 |
|---|---|---|
| 設定の名前 | `'delete_insert' => true` | `'keep_ids' => false`：特別な動きを false で書くことになる。`'recreate'`：何を作り直すかが名前から読みにくい。`'save' => '…'`：2つしかないのに値の確かめが要る |
| 既定 | false（id を保つ保存） | true：ほかから参照される子テーブルで、知らずに id が変わる |
| 入れ直しの順 | 先に全部の行を入れ、最後に古い行を消す | 先に消してから入れる：今の行のファイル名を確かめるのに、消す前の行が要る |
| 今の行の見分け方 | 使った id を、入れた行の id とは別に覚える | 入れた行の id で見分ける（今まで）：作り直す保存では新しい id になるので、同じ id を2回送られると、2回目もファイルを残してしまう ※プロンプトに無かった点 |
| 画面と送る値 | 変えない。行の id の hidden も出す | id の hidden を出さない：列ごとの配列の並びを揃えるのに id の配列を使っているので、組の部品の作りが変わる |
| 見本の並び順の列 | 消す | 残す：作り直す保存では要らないことを、見本で示せない |

## E. 課題・懸念点

| 重要度 | 内容 |
|---|---|
| 中 | 作り直す保存の組は、保存のたびに子テーブルの id が増えていく。行の数が多い組や、保存の多いコーナーでは、自動採番の値が早く進む |
| 低 | 列を消す前に、途中の空いた行に入れたファイルがあった記事は、並び順の列の順と id の順が違うことがある。列を消すと id の順に並ぶので、次に保存するまで、添付ファイルの順が変わって見えることがある |
| 低 | 作り直す保存でも、子テーブルの変更は操作ログに入らない（組の部品の課題と同じ） |

## F. セキュリティ・権限・データ整合性の注意

- ファイルの扱いは、id を保つ保存と同じ。hidden を書き換えて、ほかの行や欄のファイルを指させても残らない。同じ id を2回送っても、ファイルが付くのは1行目だけ。
- 入れ直しと古い行の削除は、本体の保存と同じトランザクションの中で行う。途中で失敗すれば、何も変わらない。使わなくなったファイルは、確定した後に消す。
- ほかのテーブルから子の行を参照するとき、子テーブルを外部キーで参照しているテーブルがあるときは使わない（利用ガイドに書いた）。

## G. テスト状況

**実施済み**（`tests/Feature/RepeatableGroupTest.php`、25件）

- 添付ファイルが、空の行を除いて画面の順に、元のファイル名つきで保存される
- 更新すると、残した行は新しい id で入れ直され、ファイルと表示名はそのまま。消した行のファイルは消え、残した行のファイルは残る
- 2つの行の間の空いた行に新しいファイルを入れても、画面の順に並ぶ
- 同じ id を2回送っても、ファイルが付くのは1行目だけ
- 定義の読み方：写真の組は `delete_insert` が false、添付ファイルの組は true で `order` が無い
- 書き方の誤り：`'delete_insert'` が true・false でない
- 写真の組（id を保つ保存）の今までのテストが、そのまま通る

全体で 393件が通る。手元の DB で、`seq` を消すマイグレーションを流し、`migrate:rollback --step=1` で列と番号が戻り、もう一度流せることを確かめた。
