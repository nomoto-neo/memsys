# 仕様メモ：子テーブルの CSV の取り込みと、取り込みでの必須（child-tables-csv-import）

- 実装プロンプト：`docs/prompt/child-tables-csv-import.md`
- 実装完了日：2026-10-25

## A. 概要

**目的・解決する課題**

CSV の取り込みで、子テーブル（`CHILD_TABLES`）を保存できるようにした。それまでは書き出しだけで、取り込みでは子テーブルを飛ばしていたので、ニュースの CSV の添付ファイルの列も取り込めなかった。あわせて、CSV の取り込みでも、アップロードの欄の必須（`UPLOAD_FILES` の `'required'`）を確かめるようにした。それまでは、一覧用画像の無い記事を CSV で登録できた。

**影響範囲**

| 範囲 | 内容 |
|---|---|
| フレームワーク | `CsvColumnSet`・`CsvReader`・`ChildTables`。複数の欄（`'repeatable'`）向けに残っていた取り込みの処理は、子テーブルの形に作り直して消した |
| 見本のサイト | ニュースの CSV で、添付ファイルの列を取り込めるようになった。一覧用画像が必須なので、ニュースの CSV では追加ができなくなった（更新だけ） |
| `csvColumns()` の書き方 | 変わらない。組の横展開を書かなければ、今までどおり親の項目だけで動く |

## B. 実装仕様

**列の読み方**（`CsvColumnSet`）

- 組の横展開（`'添付:*' => ['attach', 'group' => ['添付ファイル' => 'file_origin', '保存ファイル名' => 'file']]`）の関連の名前が、子テーブルの定義の `relation` に当たれば、組の中の値の場所を子テーブルの項目に当てる。種類は text（ファイルではない項目）・file（ファイル名）・origin（「列の名前_origin」の表示名）。
- 取り込めるのは、子テーブルの検証ルール（組の印の `{組}_group`）が `rules()` にあるときだけ。
- 組の項目（`fields`）の列が全部そろっていなければ、その組の列を全部「取り込めない列なので、無視しました」の警告にする。表示名の列は無くてよい。
- 1行のセルは番号の組に集め、番号の順に並べて、全部空欄の組を詰める。画面から送るのと同じ列ごとの配列（`{組}_group`・`{組}_id`（空）・項目・ファイル名・`_tmp`（空）・`_origin`・`_del`（空））にする。
- 保存ファイル名が空欄なのに表示名がある組と、同じ保存ファイル名が2回ある組はエラー。表示名の列が無ければ、今の行の同じファイル名の表示名を使う。
- コンストラクタの2つ目の引数は、アップロードの欄の一覧から、子テーブルの定義（関連の名前 => 定義）に変えた。

**取り込みの流れ**（`CsvReader`）

- 1つだけのアップロードの欄（`kind` が `single`）と、子テーブルの定義を集める。
- 組の列があるCSVだけ、行ごとに子テーブルの今の行（`childTableValues()`）を読み、表示名の補いと、変更の比べに使う。
- 組の中のファイル名は、1つだけの欄と同じく、今の行のファイルのほかは、その記事の保存先にあるものだけ使える（`checkImportedUploadFilename()`）。追加の行には書けない。
- 必須（`checkCsvImportRequiredUploads()`）：
  - 1つだけの欄は、ファイル名の列があればその値、無ければ今のファイルが要る。追加の行にはファイル名を書けないので、必須の欄があるコーナーでは、追加の行はいつもエラーになる
  - 子テーブルの中の欄は、組の列を取り込むときだけ、どの行にもファイルを求める
  - エラーの文は `validation.required`
- 検証は、画面と同じ `rules()`（子テーブルの検証ルールと、組の項目の要素のルールを含む）で行う。行の数の上限も効く。
- 確認画面の変更の内容は、組を1つの項目（見出しは組の外側の見出しから「:*」を除いたもの）として、変更前と変更後を並べる。1行は項目の値を「／」でつなぎ、ファイルは「ファイル名（表示名）」。

**保存**（`ChildTables`）

- 取り込みでも、組の印がある組を保存する。組の印は、組の列があったときだけ付く。
- CSV には子テーブルの行の id が無いので、取り込んだ組は行を入れ直す（id を保つ組でも、行の id が変わる）。
- ファイルは、読むときに確かめたファイル名をそのまま使う（`childTableImportedFileValue()`）。使わなくなったファイルは、画面の保存と同じく、確定の後に消す。

## C. 前提・依存

- CSV の取り込み（`CsvImport`・`CsvReader`・`CsvColumnSet`）と、組の横展開の書き出し
- 子テーブル（`ChildTables`・`ChildTableDefinitions`）
- アップロードの欄の取り込みのファイル名の確かめ（`AjaxFileUpload::checkImportedUploadFilename()`。組の中の欄の名前でも、そのまま使えた）

## D. 設計判断とトレードオフ

| 判断 | 採用 | 不採用とその理由 |
|---|---|---|
| 行の id | CSV の組の内容で入れ直す（A） | 組に id の列を書けるようにする（B）：書き出しにも id の列が出て、CSV が読みにくくなる |
| 組の列が無い CSV | 子テーブルに触らない | 空にする：親の項目だけを直したい CSV で、子テーブルが消える |
| 組の列が一部だけ | 組の列を全部無視して警告 | 足りない項目を空にする：意図せずに値が消える |
| 必須の確かめ方 | 取り込み専用の確かめ（ファイル名があればよい） | 画面と同じ `UploadRequiredRule`：画面はレコードの今の値と照らすので、保存先にある別のファイル名に差し替える取り込みが通らない。ファイル名は別の確かめで保存先にあることを見ている |
| 子テーブルの今の行を読む時点 | 組の列があるときだけ、行ごとに読む | いつも読む：組の列の無い CSV でも、行の数だけ問い合わせが増える |
| 昔の複数の欄の処理 | 子テーブルの形に作り直して消した | 残す：もう呼ばれない処理が残り、読み違える |

## E. 課題・懸念点

| 重要度 | 内容 |
|---|---|
| 中 | ニュースの CSV は、一覧用画像が必須になったので、追加ができない（更新だけ）。追加もしたいコーナーでは、必須にしないか、画面から追加する |
| 低 | 組の列がある CSV では、行ごとに子テーブルの今の行を読むので、行の数が多いと問い合わせが増える |
| 低 | 子テーブルの中の必須の欄の取り込みは、見本に無いので、テストしていない（画面の必須のテストはある） |

## F. セキュリティ・権限・データ整合性の注意

- 取り込むファイル名は、今の行のファイルか、その記事の保存先にあるものだけ。ほかの記事のファイルや、パスを含む名前は使えない（`SAFE_FILENAME` の形と、保存先にあるかを確かめる）。
- 検証は画面と同じルールで行い、行の数の上限も守る。全行を1つのトランザクションで反映し、使わなくなったファイルは確定の後に消す。

## G. テスト状況

**実施済み**

- `tests/Feature/ChildTablesTest.php`
  - 添付ファイルの組の書き出し
