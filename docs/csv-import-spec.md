# memsys CSV取り込み（CsvImport）の設計

CSVダウンロード（`App\Support\CsvDownload`）と同じ項目の定義（`csvColumns()`）を使って、CSVからデータを追加・更新する仕組みの設計メモ。野元さんとの検討で決めた内容をまとめたもの。

## 1. 基本の考え方

- 列は見出しで判断する。見出しと値の場所の対応は、ダウンロードの `csvColumns()` をそのまま使う（ダウンロードしたCSVを直して、そのまま取り込める）。
- 取り込めるのは、FormFlow の `rules()` にある項目だけ。検証（`rules()`）・保存する項目（`saveFieldNames()`）・追加で保存する項目（`additionalFields()`）・保存後の処理（`afterSave()`）は、画面からの登録・更新とまったく同じ処理を通す。画面と取り込みで結果が食い違わないようにするため。
- 取り込みは「追加」と「更新」だけ。CSVからの削除はできない。
- 流れは「アップロード → 全行を検証して確認画面 → エラーが0件なら実行」。実行は全行を1つのトランザクションで反映し、1件でも失敗したら何も反映しない。

## 2. コントローラーの書き方

確認画面と実行の両方で同じ設定を使うので、設定は `csvImportSettings()` の1か所にまとめる。どんな取り込みかが1か所で分かるよう、`CsvImportSettings` の引数には既定の値を持たせず、全部を名前付き引数で書く（ダウンロードの `downloadCsv()` と同じ考え方）。ルートから呼ばれる入口（取り込み画面・確認・実行）は、検索条件の保存（`storeSearchCondition()`）と同じくトレイト側にあるので、コントローラーには書かない。

```php
use CsvImport;

// CSV取り込みの設定
private function csvImportSettings(): CsvImportSettings
{
    return new CsvImportSettings(
        query: Member::query(),             // 取り込み先のモデル（id で探す範囲）
        name: '会員一覧',                    // 画面の見出し・取り込み記録の名前
        labelColumn: 'お名前',               // エラー・警告の「何行目」に添える列（見出し、または何列目か）
        route: 'admin.members.csv-import',  // 取り込み画面のルート名（確認は .confirm、実行は .execute）
        mode: CsvImportMode::Save,          // Save：追加・更新する／Process：保存せず処理だけ（14）
        encoding: null,                     // null なら自動判定（BOM／UTF-8／Shift_JIS）
        header: true,                       // false なら見出し無しのCSV（4-1）
        escapeFormula: true,                // ダウンロードで付けた先頭の「'」を外す
        allowInsert: false,                 // id が空欄の行（追加）を認めるか
        maxRows: null,                      // 行数の上限。null なら無制限
    );
}
```

```php
// routes/web.php（/members/{member} より前に書く）
Route::get('/members/csv-import', [AdminMemberController::class, 'csvImport'])->name('members.csv-import');
Route::post('/members/csv-import/confirm', [AdminMemberController::class, 'csvImportConfirm'])->name('members.csv-import.confirm');
Route::post('/members/csv-import/execute', [AdminMemberController::class, 'csvImportExecute'])->name('members.csv-import.execute');
```

画面（ファイルを選ぶ画面・確認画面）は、どのコーナーでも同じ部品（`admin/csv_import/`）を使う。取り込みが終わったら取り込み画面に戻り、そこに結果のメッセージを出す（続けて別のファイルを取り込めるように）。画面の「一覧へ戻る」は、コントローラーに `INDEX_ROUTE`（SearchableList の一覧のルート名）があれば出す（?back 付きで一覧の検索条件とページを復元する）。そのため、戻り先を設定に書く必要は無い。

## 3. 項目の定義（csvColumns()）の追加分

ダウンロードの書き方はそのままで、取り込みのために次を足す。

- **取り込み先の項目名**：値の場所がフォームの項目名と違う場合（リレーションをたどる場所）だけ、`'import' => '項目名'` で書く。値の場所がそのままカラム名なら書かなくてよい。

  ```php
  'カテゴリー'   => ['categories.*.id', $categories, 'import' => 'category_ids'],
  'カテゴリー:*' => ['categories.*.id', $categories, 'import' => 'category_ids'],
  ```

- **@名前の列**：取り込むには、`'import' =>` に取り込み先の項目名（複数なら配列）を書き、逆向きの変換をコントローラーの `csvCustomImport()` に書く（ダウンロードの `csvCustomColumn()` と対になるメソッド）。`'import' =>` の無い `@名前` の列は取り込まない（出力専用）。

  ```php
  '年齢'     => '@age',                                             // 出力専用
  '氏名'     => ['@fullname', 'import' => ['last_name', 'first_name']],

  private function csvCustomImport(string $key, ?string $value, CsvImportRow $row): array
  {
      return match ($key) {
          // 「山田 太郎」を姓と名に分ける
          'fullname' => array_combine(['last_name', 'first_name'], array_pad(preg_split('/[\s　]+/u', (string) $value, 2), 2, null)),
      };
  }
  ```

  戻り値は「項目名 => 値」。`'import' =>` に書いた項目だけを返せる。値がおかしいときは `$row->addError('メッセージ', '氏名')` でその行のエラーにし、空の配列を返す。
- **取り込めない列**：`rules()` に無い項目（id・登録日時・最終更新者・年齢など）は、CSVにあっても取り込まない（確認画面の「無視した列」に出す）。

### 3-1. 連番の横展開（ダウンロード側にも追加）

見出しの末尾 `:*` はそのままで、一覧を渡すかどうかで書き分ける。

| 書き方 | 見出し | データ |
|---|---|---|
| `['categories.*.id', $categories]`（一覧あり） | カテゴリー:お知らせ、カテゴリー:イベント… | 該当に1、それ以外は空欄 |
| `'attach.*.original_name'`（一覧なし） | 添付ファイル:1、添付ファイル:2… | その項目の値 |

- 連番の列の数は、書き出す前に同じ検索条件で件数を数え（`withCount()`）、対象データの中の最大件数に揃える。足りない行は空欄。
- 取り込みでは「:1」「:2」…を番号の順に集め、空欄を詰めて一覧にする。列の数はダウンロードしたときと違っていてもよい。

### 3-2. 組にした横展開

添付ファイルの「表示名」と「保存ファイル名」のように、1件ずつ組にして並べたい場合。

```php
'添付:*' => ['attach', 'group' => [
    '添付ファイル'   => 'original_name',
    '保存ファイル名' => 'filename',
]],
```

- 見出しは「添付ファイル:1, 保存ファイル名:1, 添付ファイル:2, 保存ファイル名:2, …」。外側の見出し（`'添付:*'`）は列にはならず、エラーの案内などで組の名前として使う。
- 組の数は連番の横展開と同じく、対象データの中の最大件数に揃える。
- 取り込みでは同じ番号どうしを組にし、両方空欄の組は詰める。関連が `UPLOAD_FILES` の複数の項目（`attach.*`）なら、AjaxFileUpload の決まりで `filename` → `attach`、`original_name` → `attach_origin` に取り込む（`'import' =>` は不要）。
- アップロード以外の子テーブル（明細行など）の組は、まずは書き出しだけ。取り込みが必要になったら `@名前` と同じくコントローラーに処理を書く形で足す。

## 4. 見出しの扱い

| 状態 | 扱い |
|---|---|
| id 列が無い | エラー（見出し） |
| 同じ見出しが2つある | エラー（見出し） |
| 定義にある列がCSVに無い | その項目は更新しない（CSVにある列だけ更新する） |
| 定義に無い列（打ち間違いを含む） | 無視する。確認画面に「無視した列」として警告を出す |
| 取り込めない列（`rules()` に無い、逆変換の無い `@名前`） | 無視する。確認画面に「無視した列」として警告を出す |
| 横展開の一部の列が無い（一覧に項目が増えた後のCSVではない、など） | 警告 |
| 同じ項目に対する列が複数（1セルにまとめた列と横展開の列など） | 両方の内容が食い違っていたら、その行のエラー。片方しか無ければある方を使う |

### 4-1. 見出し無しのCSV（`header: false`）

他システムから受け取るCSVのように、1行目に見出しが無いCSVも取り込めるようにする（ダウンロードの `header: false` と対になる）。

- CSVの列は、`csvColumns()` に書いた順番で、全部の列が並んでいる前提で読む（1行目からデータとして読む）。
- 取り込めない列（id 以外の出力専用の列：登録日時・最終更新者・逆変換の無い `@名前` など）も、その位置に列がある前提で読み飛ばす。
- 全部の列がある前提なので、「CSVにある列だけ更新する」ではなく、取り込める項目はすべて更新する。
- 行ごとに列の数を確かめ、定義から決まる列の数と違う行はエラーにする。
- `csvColumns()` に id が無い場合は、定義のエラー（書き出す前・読む前に例外）。
- 横展開（区分表・連番・組）は使わない。見出し無しのCSVは他システムとの連携のような特殊な場面のためのもので、横展開は必要ないため。ダウンロードでも取り込みでも、見出し無しの動作モードで `csvColumns()` に横展開（見出しが `:*` で終わる列）があれば、定義のエラー（システムエラー）にする。見出し無しで使う画面は、横展開の無い定義にする。
- 確認画面の「無視した列」の警告は出さない（見出しが無いので、打ち間違いの列も無い）。確認画面の見出しには、定義の見出しを使う。

## 5. 値の読み方

- **空欄**：NULL にする（ダウンロードで NULL を空欄で出しているので、往復しても値が変わらない）。必須の項目が空欄なら `rules()` の検証でエラーになる。
- **検証する入力の作り方**：更新なら「DBの今の値（`inputFromModel()`）に、CSVにある列の値を上書きしたもの」、追加なら「`defaultInput()` に、CSVにある列の値を上書きしたもの」を `rules()` で検証する。CSVに無い必須項目でエラーにならないようにするため。
- **一覧の表示名 → 値**：`[値の場所, 一覧]` の列は、表示名を一覧の値に戻す。一覧に無い表示名はその行のエラー。横展開の列は、1が入っている列の値を集める（1と空欄以外はエラー）。
- **日付（`|date`）**：「4桁の年-月-日」「4桁の年/月/日」だけを受け付ける（月・日は1桁でも可。Excel が「2026/9/29」に書き換えるため）。日時の項目は、後ろに「時:分」「時:分:秒」が付いた形も受け付ける。形が合っても存在しない日（2026/2/30 など）はエラー。これ以外の形は日付として解釈しない（ゴミデータを日付と判別しないため）。
- **3桁区切り（`|number`）**：「先頭が1〜3桁で、その後が『カンマ＋3桁』の繰り返し」の形（`12,345`・`1,234,567`、小数・マイナス付きも可）だけカンマを外す。それ以外でカンマを含むもの（`1,,2`・`12,34` など）はエラー。
- **`|format`**：数値として読める値に戻す（`000012` → 12）。
- **数式の無害化**：`escapeFormula: true` なら、ダウンロードで付けた先頭の「'」を外してから読む。
- **文字コード**：ファイル全体で判定する。BOM があれば UTF-8 として全体が正しいか、無ければまず UTF-8 として、だめなら Shift_JIS（CP932）として全体が正しいかを見る。どれにも当てはまらなければ「文字コードが判別できない（混在している）」エラー。`encoding:` で指定した場合は、その文字コードとして全体が正しいかだけを見る。

## 6. アップロード項目（ファイル名）の取り込み

### 6-1. commitUploads() の変更（画面からの登録にも効く）

- 入力に、その項目のキー（単数なら `field`・`field_tmp`・`field_del`・`field_origin`、複数なら `field`）が1つも無ければ、その項目は何もしない。CSVにアップロードの列が無いときに、既存のファイルを「外された」と判断して消さないようにするため。画面のフォームは4つの hidden を必ず送るので、画面からの登録・更新の動きは変わらない。

### 6-2. ファイル名の変更（取り込みのときだけ）

バッチ処理などで実ファイルの名前を変えた後、新しい名前だけをCSVで反映したい場合のため。画面のフォームは、今までどおり「hidden の値が DB の値と一致するときだけ採用」のまま（hidden は書き換えられるため）。取り込みのときだけ `commitUploads()` に「名前の変更を認める」指定を渡す。

- 新しいファイル名は、今のアップロードと同じ安全な形式（`/` や `..` を含まない）で検証する。
- ファイル名だけを受け取り、必ずそのレコードの保存先（例：`news/000/000012/`）の中で探す。実在しなければその行のエラー。
- 古いファイルは、更新前後でレコード全体のどの項目からも参照されなくなったときだけ、トランザクションの確定後に消す（今の `commitUploads()` の差分の仕組みのまま）。実ファイルが既に無ければ何もしない。
- 複数の項目（添付ファイル）は、CSVにその列があれば、そこに全部のファイルが入っている前提。3個が2個になっていれば、消えた1個は外されたものとして扱う。並び順はCSVの順。
- 保存ファイル名が空欄で表示名だけある組はエラー。
- 表示名の列が無く保存ファイル名の列だけあるときは、ファイル名が今と同じファイルは今の表示名のまま、新しい名前のファイルは表示名なし（NULL）。単数の項目（一覧用画像など）も同じ。名前を変えたファイルの表示名を残したいときは、表示名の列も一緒に取り込む（ダウンロードしたCSVには表示名の列が入っている）。保存ファイル名の列が無く表示名の列だけあるときは、どのファイルの表示名か決められないので、その列は無視する（確認画面に「無視した列」として警告を出す）。
- 単数の項目で表示名の列だけあるときは、今のファイルの表示名だけを変える（ファイルが無ければその行のエラー）。ファイル名が空欄で表示名だけあるときもエラー。
- 同じ保存ファイル名が1行の中に2回出てきたら、その行のエラー。
- ファイル名の拡張子は、その項目で受け付けている種類（画像の項目なら jpg・png など）だけを認める（同じ保存先にある別の項目のファイル、たとえば添付ファイルの PDF を画像の項目に指定させないため）。
- 追加の行（id が空欄）に保存ファイル名があればエラー（保存先は id が決まってから作られるため）。

### 6-3. 表示名（元のファイル名）

- 表示名が空欄なら空欄のまま（NULL）にする。ファイル名はランダムな文字列で、表示名の代わりにしても意味が無いため。画面からのアップロード（AjaxFileUpload）でも同じ扱いにそろえる。
- あわせて直すところ：
  - `t_news_attachments.original_name` を NULL 可にする（マイグレーション）。
  - `AjaxFileUpload::commitRepeatableUploadField()` の「表示名が無ければファイル名を入れる」を外す。
  - 表示名が無いときは、リンクの文字を「添付ファイル1」「添付ファイル2」…にする（訪問者向けのニュース詳細、管理画面の確認・詳細・入力画面）。download 属性はそのまま付ける。値が空の download 属性は「ファイル名はブラウザが決める」という意味で、不具合は無い（保存されるファイル名はサーバー上のファイル名になる）。
  - 問い合わせの通知メールの添付ファイル名は、メールの添付には名前が必要なので、表示名が無ければ保存ファイル名を使う（今のまま）。

## 7. 重複（DBの一意制約）

- 既存データとの重複：`rules()` の `Rule::unique()`（自分の行は除外）が1行ずつの検証で見る。
- CSVの中での重複：`rules()` の中から `Rule::unique` が付いている項目を探し、全行の値を集めて、同じ値が2回出てきたら両方の行をエラーにする。
- 入れ替え（A の値を B に、B の値を A に）：1行ずつの検証で「既存の値と重複」のエラーになる。正しく判定するのは難しいので、エラーのままにする（2回に分けて取り込んでもらう）。
- CSVの中で同じ id が2回出てくる、DB に無い id（削除済みを含む）：その行のエラー。
- それでも実行時に制約違反が起きたら（確認の後に他の人が同じ値を登録した、など）、全件を取り消し、何行目で止まったかをエラーで出す。

## 8. 確認画面

- 件数の集計：追加・更新・変更なし・エラー・警告の件数。
- 列の警告：無視した列、横展開の一部の列が無い、など。
- データのエラー・警告：何行目の、どの列が、なぜ。`labelColumn` を指定すると「2行目（山田太郎）」のように、その行の指定した列の値を添える（10文字を超えたら先頭10文字に「...」、空欄なら添えない。実行を中止したときのメッセージも同じ）。最初の30行まで表示し、それより多ければ「ほかにN行あります（最初の30行だけを表示しています）」と出す。変更の例（5件）・処理だけのモードの読み込んだ内容（30行）も同じく、省略した件数を出す。
- 正常な行（追加・更新）は1行ずつ並べず、項目ごとの変更件数（更新で変わる件数・追加で入る件数）だけを表で出す。項目ごとに「例を見る」で、変更の例（最初の5件、何行目・変更前 → 変更後）を開いて見られる。直したつもりの無い項目が大量に変わっていること（Excel で電話番号の先頭の0が落ちた、別の列に貼り付けた、など）に、行数に関係なく気づけるようにするため。
- エラーが0件のときだけ「取り込む」ボタンを出す。
- 変更の無い行は、実行しても保存しない（全行を保存すると、全部の行の更新日時と「最終更新者」が取り込んだ人に書き換わってしまうため）。

## 9. 確認から実行まで

- アップロードしたファイルは一時保存しておき、実行時にもう一度読んで、全行をもう一度検証してから反映する。
- 確認画面を経由した1回だけの実行にするため、お問い合わせの confirm_token と同じ仕組みを使う。
- **衝突チェック（全体）**：確認時に、CSVに含まれる id のデータごとの更新日時（DBの値の文字列そのまま）を控えておき（一時ファイルの隣に置く）、実行時に1件でも変わっていた・削除されていたら取り込み全体をエラーにする（確認画面を見てから実行するまでの間に誰かが変えた、削除した場合）。エラーのメッセージには、変わった行を「3行目（山田太郎）」の形で出す（5行まで）。画面から何も変えずに「更新する」を押しただけのときは、更新日時が変わらないのでエラーにならない（データも変わっていないので、取り込んで問題ない）。
- **衝突チェック（行ごと）**：CSVに「更新日時」の列があれば、行ごとに DB の更新日時と比べ、DB の方が新しい行は警告にする。更新日時の列は取り込まず、ダウンロードした時点の値のまま残しておく（他の列を直しても書き換えない）。Excel で保存すると日時が「2026/9/29 6:15」の形に変わり秒が落ちるので、文字列ではなく日時として読み、CSVの値にある細かさ（秒・分・日）までで比べる（秒が無ければ、同じ分のうちの変更は見分けられない）。日時として読めない値は比べずに警告だけ出す。列が無い・空欄の行は比べない（ダウンロードしてから取り込むまでの間に画面から変更されたもの）。警告なので、そのまま上書きして取り込むこともできる。

## 10. エラーと警告の一覧

| 種類 | 例 | 取り込めるか |
|---|---|---|
| エラー（ファイル） | 文字コードが判別できない、行数の上限を超えた | 不可 |
| エラー（見出し） | id 列が無い、同じ見出しが2つある | 不可 |
| エラー（定義） | 見出し無しなのに横展開の列がある（ダウンロードでも同じ）、定義に id が無い | 不可 |
| エラー（行） | 見出し無しで列の数が違う、検証エラー、一覧に無い表示名、日付・数値の形が不正、同じ項目の列どうしの食い違い、存在しない id、CSVの中の重複、保存ファイルが実在しない、`allowInsert: false` なのに id が空欄 | 不可 |
| エラー（実行時） | 確認後に対象の行が変更・削除された、DB の制約違反 | 不可（全件取り消し） |
| 警告（列） | 無視した列、横展開の一部の列が無い | 可 |
| 警告（行） | 行ごとの更新日時が DB の方が新しい | 可 |

## 12. 件数の上限・性能

- 行数の上限は `maxRows:` で指定する。指定しなければ無制限。
- 実際には、サーバーのアップロードの上限（`upload_max_filesize`・`post_max_size`）と実行時間の上限が先に効く。確認画面は最初の30行までしか並べないので、表示の重さは件数に比例しない。

## 13. 取り込みに処理を組み込む（フック）

取り込みは、単純にDBへ入れるだけでなく、読み込んだデータを使った処理を組み込めるようにする。コントローラーに同じ名前のメソッドを書いたときだけ呼ばれる（FormFlow の `afterSave()` などと同じ仕組み）。

| メソッド | 呼ばれるとき | 使いどころの例 |
|---|---|---|
| `afterSave($record, $validated)` | 1行保存するたび（画面からの保存と共通） | 関連テーブルの `sync()`。画面と取り込みで同じ処理 |
| `validateCsvRows(CsvImportResult $result)` | 全行を1行ずつ検証した後（確認画面・実行の両方） | 行をまたいだチェック（CSVの中の合計・同じ組み合わせの重複）、他のテーブルとの突き合わせ。`$row->addError()`・`$row->addWarning()` で結果に足す |
| `afterCsvImportRow(CsvImportRow $row)` | 1行保存するたび（取り込みのときだけ）。トランザクションの中 | 取り込みのときだけ行う処理（履歴テーブルへの記録、ポイントの付与など）。例外を投げると全件取り消し |
| `afterCsvImport(CsvImportResult $result)` | 全件の確定（コミット）と取り込み記録の後 | 取り込み結果の通知メール、外部システムへの連携、キューへの登録。ここで例外が起きても取り込み自体は確定済み（エラーはログに残し、画面に「取り込み後の処理でエラー」と出す） |

- `CsvImportRow` は1行分の情報：何行目か（`line`）、対象のレコード（`record`。追加なら保存後にセットされる）、CSVのセル（`cell('見出し')`）、検証済みの値（`validated`）、追加・更新・変更なし（`action`）、エラー・警告。
- `CsvImportResult` は全体の情報：全行（`rows`）、件数、ファイル・見出しのエラーと警告。
- `validateCsvRows()` は確認画面と実行の両方で呼ばれるので、確認画面で出たエラーと実行時の判断が食い違わない。

## 14. 処理だけのモード（`mode: CsvImportMode::Process`）

読み込んだデータをモデルに保存せず、コントローラーに書いた処理に渡すモード。入金データの消し込み、ポイントの一括付与、在庫数の加算、一斉メールの宛先リストのように、「CSVの1行 = 1レコードの上書き」ではない取り込みのため。

```php
// 検証済みの全行を受け取って処理する（トランザクションの中）。
// 戻り値は完了の画面に出すメッセージ（null なら「N件を処理しました。」）
private function processCsvRows(CsvImportResult $result): ?string
{
    foreach ($result->rows as $row) {
        $row->record->increment('point', $row->validated['point']);
    }

    return count($result->rows).'件のポイントを付与しました。';
}
```

- 列の定義（`csvColumns()`）・検証（`rules()`）・値の読み方・確認画面・確認から実行までの流れ（一時ファイル、confirm_token）・取り込み記録は、保存するモードと同じ。
- 検証する入力は、CSVにある列の値だけ（DBの今の値は重ねない）。CSVに無い必須の項目はエラーになる。
- id の列は、定義にあれば使う（その行の `record` に DB のレコードが入る。存在しない id はエラー。空欄は `allowInsert: true` のときだけ認め、`record` は null）。定義に無ければ使わない（全行の `record` が null）。
- 保存するモードと違い、変更の有無の比較（変更なしの行を飛ばす）、アップロード項目の反映はしない。
- 確認画面には、処理する行の最初の30行を、読み込んだ値で表示する（閉じた状態で出し、開いて確かめる）。
- 1つのコントローラーには取り込みを1つだけ書ける（`csvColumns()`・`rules()` がコントローラーに1つのため）。保存する取り込みと別に処理だけの取り込みを作るときは、別のコントローラーにする。

- アップロード以外の子テーブル（明細行など）の組の取り込み（書き出しはできる）。
- 入れ替え（A↔B）の一意制約の正しい判定。
