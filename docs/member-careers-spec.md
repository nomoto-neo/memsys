# 仕様メモ：子テーブルの最初の枠の数（initial）と、会員の経歴（member-careers）

- 実装プロンプト：`docs/prompt/member-careers.md`
- 実装完了日：2026-10-25

## A. 概要

**目的・解決する課題**

子テーブル（`CHILD_TABLES`）に、入力の画面に最初から並べる枠の数（`'initial'`）を足した。最初から10枠を並べ、「行を足す」で20枠まで足せる、のような画面を書けるようにするため。

その見本として、会員に経歴（学歴・職歴）を足した。マイページの編集と管理画面の会員の編集で年・月・内容を入力し、履歴書の PDF（HTML から作るものと、定型紙に載せるもの）の学歴・職歴の欄に出す。

**影響範囲**

| 範囲 | 内容 |
|---|---|
| フレームワーク | 子テーブルの定義に `initial` を足した。画面の部品が、最初に並べる枠の数を読む |
| 見本のサイト | 会員の経歴のテーブル・モデル・入力欄・表示・履歴書の PDF。退会のときに経歴も消す |
| CSV | 会員の CSV には足していない |

## B. 実装仕様

**`initial`**（`ChildTableDefinitions`・`_repeatable_group`）

- 入力の画面に最初から並べる枠の数。行がそれより少なければ、空の枠で埋める。省略すると1（今までと同じ）。
- 1以上で `max` 以下。`fixed` と同時に書いたら `LogicException`（「…は、'initial'と'fixed'を同時に書けません。'fixed'を書くと、その数の枠を並べます。」）。範囲の外なら「…の'initial'は、1から'max'までの数で書いてください。」。
- 定義の形の `initial` は、固定の枠なら `fixed` の数、書いていなければ1が入る。
- 「行を足す」と × は普通に出る。画面の上で × で減らしても、開き直すと `initial` の数に戻る。

**経歴のテーブル**（`t_member_careers`）

| 列 | 型 | 中身 |
|---|---|---|
| `member_id` | 会員の id（外部キー制約なし。ほかの子テーブルと同じ） | 親 |
| `year` | `unsignedSmallInteger` | 年 |
| `month` | `unsignedTinyInteger` | 月 |
| `content` | `string`（255） | 内容 |

- モデル `App\Models\MemberCareer`、`Member::careers()`（id の順）。

**定義と検証**（`Admin\MemberController`・`MypageController`）

```php
'careers' => ['relation' => 'careers', 'fields' => ['year', 'month', 'content'], 'delete_insert' => true, 'initial' => 10, 'max' => 20],
```

- 要素の検証ルールは `MemberCareer::rules()` にまとめ、2つのコントローラーの `rules()` に足す。年は1900から今年まで、月は1〜12、内容は255文字まで。空の行は検証の前に除かれるので、残った行は3つとも必須にしている（年・月・内容のどれか1つでも入れた行は、3つとも要る）。
- 退会（`MypageController::destroy()`）のときに、`deleteChildTables()` で経歴の行も消す。退会は会員の行を直接消すので、FormFlow の削除を通らないため。

**画面**

- 行の部分ビュー `resources/views/_member_career_row.blade.php` を、管理画面とマイページで使う。入力の画面は「年（数）・月（選択）・内容（文字）」を横に並べ、確認・詳細の画面は「2020年4月　〇〇大学 入学」の1行にする。
- 管理画面の会員の入力欄（`admin/members/_fields`）と、マイページの編集（`mypage/edit`）に、「経歴（学歴・職歴）」の欄を足した。行を足すボタンの文言は「経歴を追加」。2つの編集の画面で `repeatable_group.js` を読み込む。
- マイページの表示（`mypage/index`）に、経歴の一覧を足した。

**履歴書の PDF**

- HTML から作る履歴書（`pdf/resume.blade.php`）：学歴・職歴の表の上の行から、経歴を入れる。行は14行で、経歴が14行より多いときは全部を出す。
- 定型紙の履歴書（`pdf/resume_on_sheet.blade.php`）：1ページ目の学歴・職歴の欄に15行まで、残りを2ページ目の欄に続ける。行は10mmずつ、列の境目は37.6mmと52.6mm（2ページ目の免許・資格の欄の測った寸法に合わせた）。1ページ目の1行目の上端126.4mm、2ページ目の1行目の上端25.4mmは、様式例の一般的な寸法から見積もった位置。

**見本のデータ**

- `MemberSeeder` で、1人目の会員に経歴を3行入れる。

## C. 前提・依存

- 子テーブルの仕組み（`ChildTables`・`ChildTableDefinitions`・`_repeatable_group`・`repeatable_group.js`）
- 履歴書の PDF（`PdfDownload` の `downloadPdf()`・`downloadPdfOnSheet()`）と定型紙 `resources/pdf-sheets/resume_a4.pdf`
- マイページのメールアドレスの変更の保留（`EmailChange`）。保留した入力にも経歴が入り、確認コードの入力の後に、同じ保存（`saveValidated()`）で保存される

## D. 設計判断とトレードオフ

| 判断 | 採用 | 不採用とその理由 |
|---|---|---|
| 最初の枠の数のキー | 新しく `initial` を足す | `min` を使う：`min` は入っている行の下限の検証で、`min => 10` にすると10行入れないと保存できない |
| × で減らしたとき | 画面の上では減ってよい。開き直すと戻る | `initial` より減らせなくする：空の枠は保存されないので、減らせなくする意味が小さい |
| 年と月 | 別々の列（数） | 1つの列（日付や「2020/04」）：履歴書で年と月を別の欄に書く |
| 保存 | `delete_insert`、並び順の列なし | id を保つ：経歴の行をほかから参照しない |
| 検証ルールの置き場所 | `MemberCareer::rules()` にまとめる | 2つのコントローラーに同じルールを書く：直し忘れて食い違う |
| 行の部分ビュー | `resources/views/` 直下の `_member_career_row`（どの画面からも使う部分ビュー） | 管理画面とマイページに別々に書く：同じ行の見た目が食い違う |
| 定型紙の位置 | 見積もった位置に置き、後で直す（A） | 寸法を測ってから置く（B）：手元に PDF を画像にする道具が無く、用紙を見られない |

## E. 課題・懸念点

| 重要度 | 内容 |
|---|---|
| 中 | 定型紙の履歴書の学歴・職歴の位置は見積もり。用紙の罫線とずれている見込みがあるので、PDF を出して確かめ、`resume_on_sheet.blade.php` の上端の数を直す必要がある |
| 低 | 定型紙の1ページ目の行の数（15行）も見積もり。欄の行が少なければ、2ページ目に続ける行の数も変わる |
| 低 | 会員の CSV では、経歴を書き出しも取り込みもしない |

## F. セキュリティ・権限・データ整合性の注意

- マイページは、ログイン中の本人の経歴だけを保存する（会員はいつも `Auth::user()`）。行の id を送られても `delete_insert` で入れ直すので、ほかの会員の行には触れない。
- 行の数は20行までを、画面だけでなく保存のときの検証でも守る。
- 退会したときは、経歴の行も消す（個人情報を残さない）。
