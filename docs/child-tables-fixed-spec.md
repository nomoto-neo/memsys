# 仕様メモ：子テーブルの固定の枠（child-tables-fixed）

- 実装プロンプト：`docs/prompt/child-tables-fixed.md`
- 実装完了日：2026-10-25

## A. 概要

**目的・解決する課題**

子テーブル（`CHILD_TABLES`）の画面に、最初から決まった数の枠を並べる形（固定の枠）を足した。経歴の年月と内容を10枠並べて、入れた分だけ子テーブルに保存する、のように、行を増減させずに入力する画面を、同じ仕組みで書けるようにするため。

見本は、ニュースの添付ファイルを4枠にした。会員の経歴の見本（マイページ・管理画面・履歴書の PDF）は、この後の別の作業にする。

**影響範囲**

| 範囲 | 内容 |
|---|---|
| フレームワーク | 子テーブルの定義に `fixed` を足した。画面の部品と JS が、固定の枠では行を足さず消さない |
| 見本のサイト | ニュースの添付ファイルを `'fixed' => 4` にした（上限は5から4へ） |
| 保存・検証 | 変わらない。上限が `fixed` の数になるだけ |

## B. 実装仕様

**定義**（`ChildTableDefinitions`）

```php
'attach' => ['relation' => 'attach', 'fields' => ['file'], 'delete_insert' => true, 'fixed' => 4],
```

- `fixed` は1以上の数。書けば、`max` もその数になる（定義の形の `max` に入る）。
- `fixed` と `max` は、どちらか1つを必ず書く。同時に書いたら `LogicException`：「…のCHILD_TABLESの「attach」は、'fixed'と'max'を同時に書けません。'fixed'を書くと、行の数の上限もその数になります。」
- `fixed` が1未満なら「…に、固定の枠の数を'fixed'に1以上の数で書いてください。」。どちらも無ければ、今までの `max` の例外。
- `min` は一緒に書ける（`fixed` の数まで）。
- 定義の形に `fixed`（?int）を足した。

**画面**（`_repeatable_group`・`_repeatable_group_row`）

- 入力の画面に並べる枠の数は、固定の枠なら「行の数」と「`fixed`」の大きいほう。保存してある行（または入力し直した行）を先に並べ、足りない分を空の枠で埋める。
- 固定の枠では、「行を足す」のボタンを出さない。行の部分ビューに `'removable' => false` を渡し、行の × も出さない。
- 組の要素に `data-fixed="1"` を付ける。
- 確認・詳細の画面は変えていない（入っている行だけを並べる）。

**JS**

- `repeatable_group.js`：`data-fixed` の組では、`addRow()` が行を足さずに null を返し、`removeRow()` は何もしない。
- `ajax_upload.js`：ファイルだけの組でも、`data-fixed` の組では「ファイルを削除」で行を消さず、欄を空にするだけ。まとめて選んだときは、空いている枠に入れ、行は足せないので、入りきらない分は今の文（「ファイルは4件までです。2件は追加しませんでした。」）で知らせる。

## C. 前提・依存

- 子テーブルの仕組み（`ChildTables`・`ChildTableDefinitions`）と画面の部品
- 「ファイルを削除」で行を消す動き（ファイルだけの組）と、まとめて選ぶ動き（`ajax_upload.js`）
- 保存の前に空の行を除く動き（`dropEmptyChildRows()`）。空の枠はこれで除かれる

## D. 設計判断とトレードオフ

| 判断 | 採用 | 不採用とその理由 |
|---|---|---|
| 書く場所 | 子テーブルの定義の `fixed` | 画面の部品に渡す：上限との関係を、画面を開くまで確かめられない |
| 上限 | `fixed` を書けば上限もその数。`max` と同時には書かせない | `fixed` と `max` を別々に書く：画面に出ない数の行を許すことになり、意味が無い。上限そのものは、書き換えた送信を断るのに要る |
| 枠より多い行 | 全部出す。そのまま保存すると上限で断る | 枠の数で切る：画面に出ない行が保存のときに消える |
| 「ファイルを削除」 | 固定の枠では行を消さない | 今のファイルだけの組と同じく行ごと消す：枠の数が減る |
| 属性の出し方 | `data-fixed` を `{!! !!}` で出す | `@endif@if` と続けて書く：Blade が2つ目の `@if` を読めず、画面が壊れる ※実装の途中で分かった点 |

## E. 課題・懸念点

| 重要度 | 内容 |
|---|---|
| 中 | 添付ファイルの上限が5から4になった。5件持つ記事は、1件消さないと保存できない |
| 低 | 固定の枠でも、行の中のファイルの欄のエラーの場所は `photos_image.0` の形で、詰めた後の番号になる（今までと同じ） |

## F. セキュリティ・権限・データ整合性の注意

- 画面に出すのは `fixed` の枠だけでも、上限の検証（`max`）で、書き換えた送信で多い行を送られても断る。
- 保存・ファイルの扱い・必須の確かめは、今までと同じ。

## G. テスト状況

**実施済み**（`tests/Feature/ChildTablesTest.php`、`tests/Feature/UploadFieldTest.php`）

- 新規登録の画面に、添付ファイルの枠が4つ（とひな型）出て、`data-fixed` が付き、「ファイルを追加」と × が出ない。写真は今までどおり「写真を追加」と × が出る
- 添付ファイルが1件の記事の編集の画面でも4枠。5件の記事は5枠出て、そのまま保存すると「4件まで」で断り、行は変わらない
- 定義の読み方：添付ファイルの `fixed` と `max` が4、写真の `fixed` が null
- 書き方の誤り：`fixed` と `max` を同時に書く、`fixed` が1未満
- 空の枠を除き、間を空けて入れても詰めて保存されること（今までのテストのまま通る）

全体で 406件が通る。
