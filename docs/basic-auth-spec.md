# 仕様メモ：管理画面からのベーシック認証の切り替え（basic-auth）

- 実装プロンプト：`docs/prompt/basic-auth.md`
- 実装完了日：2026-10-27

## A. 概要

**目的・解決する課題**

公開前のサイトや管理画面の入口を、運用する人が管理画面からベーシック認証で守れるようにした。今までは、サーバーで `.htaccess` と `.htpasswd` を手で書く必要があった。Laravel のミドルウェアで認証すると、Laravel を通らない `public` の下の HTML や画像に掛からないので、認証は Apache に任せ、管理画面は目印のファイルと `.htpasswd` を作るだけにした。訪問者画面と管理画面で、オンオフとユーザーを別々に持つ。

**影響範囲**

| 範囲 | 内容 |
|---|---|
| フレームワーク | テーブル `basic_auth_users` とモデル `BasicAuthUser`、`BasicAuth`（範囲ごとの目印のファイル・`.htpasswd`・締め出さない確かめ・操作ログ）、画面 `BasicAuthController` と `neobit::admin.basic_auth.index`、操作の種類3つ |
| 見本のサイト | ルート・メニュー（「セキュリティ」の「ベーシック認証」） |
| DB | `basic_auth_users` テーブルを足した |
| サーバー | VirtualHost に決まりを書き、Apache を読み直す（サーバーを管理する人。1回だけ）。`public/.htaccess` は変えない |

## B. 実装仕様

**範囲**（`BasicAuth::AREAS`）

| 範囲 | 名前 | 掛ける URL |
|---|---|---|
| `site` | 訪問者画面 | `/admin`・`/up`・`/mail/unsubscribe` の外の全部 |
| `admin` | 管理画面 | `/admin` の下の全部 |

**ファイル**（`storage/app/basic-auth/`。無ければ PHP が作る）

| ファイル | 中身 |
|---|---|
| `site.on`・`admin.on` | あればその範囲に掛ける。中身は空 |
| `site.htpasswd`・`admin.htpasswd` | その範囲の「ユーザー名:bcrypt のハッシュ」を1行に1人、ユーザー名の順。隣に書いてから置き換える |

**VirtualHost の決まり**（利用ガイドの25章「ベーシック認証」）

- `<Directory "…/public">` の中に、範囲ごとの `<If>` を1つずつ。目印のファイルがあり、その範囲の URL なら、その範囲の `.htpasswd` で `Require valid-user`。
- `AuthName` は範囲ごとに分ける（訪問者画面は `Restricted`、管理画面は `RestrictedAdmin`）。

**テーブル**（`basic_auth_users`）

- `area`：`site` か `admin`。
- `username`：50文字まで。照合順序 `utf8mb4_bin`（Apache は大文字と小文字を別物にするため）。`area` と `username` の組で一意。
- `password`：`password_hash(…, PASSWORD_BCRYPT)` の `$2y$`。`.htpasswd` にそのまま書く。

**画面**（`BasicAuthController`）

- ルートは案件が「頭.index」（GET）「頭.update」（PATCH、`{area}`）「頭.store」（POST、`{area}`）「頭.destroy」（DELETE、`{basicAuthUser}`）で書く。見本は `{area}` を `site`・`admin` に絞る。
- 範囲ごとに1つの枠：「ベーシック認証を掛ける」のチェックと「保存する」、ユーザー名・パスワードの欄と「追加」、ユーザー名と追加した日の一覧、行ごとの削除（確認の窓）。パスワードは出さない。
- 入力のエラーは、範囲の名前のエラーの入れ物（`site`・`admin`）に入れ、その範囲の枠にだけ出す。
- 上に「サーバーの設定（VirtualHost）に決まりを書いてあるときだけ働きます。」。
- 保存の文は「訪問者画面のベーシック認証の設定を保存しました。」「管理画面のユーザー「staff」を追加しました。」など、範囲の名前を付ける。

**検証と締め出さない確かめ**（範囲ごと）

| 確かめること | エラーの文 |
|---|---|
| ユーザー名の形（半角の英数字と `-`・`_`・`.`、50文字まで） | ユーザー名は、半角の英数字と - _ . で入力してください。 |
| 同じ範囲の中のユーザー名の二重の登録 | このユーザー名は、もう登録されています。 |
| パスワード（8文字以上72文字まで） | 決まりの文 |
| ユーザーが0人の範囲に掛けようとした | ユーザーがいないので、ベーシック認証を掛けられません。先にユーザーを追加してください。 |
| 掛けている範囲の最後のユーザーを削除しようとした | ベーシック認証を掛けている間は、最後のユーザーを削除できません。 |

**操作ログ**

| 操作の種類 | いつ | 補足 |
|---|---|---|
| `basic_auth_change`（ベーシック認証の変更） | 範囲の掛けるかが変わったとき | 例：「訪問者画面：掛ける」 |
| `basic_auth_user_add`（ベーシック認証のユーザーの追加） | ユーザーを追加したとき | 例：「管理画面：staff」 |
| `basic_auth_user_delete`（ベーシック認証のユーザーの削除） | ユーザーを削除したとき | 例：「管理画面：staff」 |

パスワードは残さない。

## C. 前提・依存

- サーバーが Apache 2.4（`<If>` と、`.htpasswd` の bcrypt を読める版）
- PHP-FPM が `storage` に書けること（今のサーバーの権限の形のまま）
- 管理者だけが入れるルートのグループ（`acl.manager`）

## D. 設計判断とトレードオフ

| 判断 | 採用 | 不採用とその理由 |
|---|---|---|
| 認証する場所 | Apache | Laravel のミドルウェア：Laravel を通らない `public` の下のファイルに掛からない |
| 決まりを書く場所 | VirtualHost | `public/.htaccess`：肥大させたくない。`AuthUserFile` はサーバーごとの絶対パスが要り、`.htaccess` に書くとサーバーごとに中身が変わる |
| オンオフ | 目印のファイルを作る・消す | `.htaccess` を書き換える：apache にファイルを書かせることになり、書き方の誤りでサイト全体が止まる |
| ユーザー | 範囲ごとに別々（`.htpasswd` も2つ） | 両方で共通：公開前の確認に渡すユーザーで、管理画面にも入れてしまう |
| AuthName | 範囲ごとに分ける | 同じにする：ブラウザが ID とパスワードをホスト名と AuthName の組ごとに覚えるので、訪問者画面で入れたものを管理画面にも送り、同じユーザーが両方にあれば窓が出ずに通る |
| ユーザーの置き場所 | DB のテーブルから `.htpasswd` を書き出す | `.htpasswd` だけ：追加した日を持てず、壊れたときに作り直せない |
| 忘れたときの外し方 | サーバーで `rm` | 外すコマンド：目印のファイルを消すだけなので要らない |
| 操作ログ | 新しい操作の種類で、範囲とユーザー名を補足に | 登録・削除の種類で対象に：アプリのモデルの短い名前に足す必要がある |

## E. 課題・懸念点

| 重要度 | 内容 |
|---|---|
| 中 | VirtualHost に決まりを書いていないサーバーでは、画面で掛けても働かない。画面に注意を出している |
| 低 | パスワードの総当たりを止めない（Apache の側のため）。`docs/security-issues.md` の11 |
| 低 | パスワードの72文字は文字の数で数える。bcrypt は72バイトまでしか読まないので、全角を多く使うと後ろが効かない |
| 低 | 掛けている状態は、ファイルの有無で決まる。サーバーで手で `touch`・`rm` したときは、操作ログに残らない |

## F. セキュリティ・権限・データ整合性の注意

- 画面を開けるのは管理者だけ（`acl.manager`）。
- `.htpasswd` は `storage` の下（`public` の外）なので、URL から読まれない。
- パスワードは bcrypt のハッシュだけを持ち、画面にも操作ログにも出さない。
- 範囲ごとに、最後のユーザーの削除と、ユーザーの無いときのオンを止め、画面からは締め出されない。

## G. テスト状況

**実施済み**（`tests/Feature/BasicAuthTest.php`、3件。storage はテストのあいだだけの一時のディレクトリ）

- ユーザーがいない範囲には掛けられず、エラーはその範囲の入れ物に入る
- 範囲ごとにユーザーを追加すると、その範囲の `.htpasswd` だけに bcrypt のハッシュで書く（`password_verify` で合う）
- 訪問者画面にだけ掛けると `site.on` だけができる。掛けている範囲の最後のユーザーは削除できず、掛けていない範囲は削除できる。外すと削除できて `.htpasswd` が空になる
- 操作ログの種類と順番、補足の範囲とユーザー名。パスワードが残らない
- `:` を含むユーザー名・同じ範囲の二重の登録・短いパスワードを断る。範囲が違えば同じユーザー名でよく、大文字と小文字は別のユーザー。知らない範囲は断る
- 管理者でないスタッフは開けない

全体で 463件が通る。
