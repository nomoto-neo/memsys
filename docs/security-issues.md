# セキュリティ面の課題

2026-10-04 の時点で、まだ対応していない課題をまとめたものです。対応したら、その項目の「状態」を書き換え、利用ガイド（`neobit-framework-guide.md`）の該当する章に使い方を書きます。

認証（2段階認証・パスキー・試行制限）と記録（操作ログ・管理画面の回数の制限・報告のメール）は、対応済みです。ここには載せていません。

## 優先して対応したいもの

### 1. メールアドレスの変更に、確認を挟む

- **今の状態**：マイページでメールアドレスを変えると、すぐ切り替わります（`MypageController::update()`）。変わる前と後の両方のアドレスに、お知らせのメールは届きます。
- **なぜ要るか**：メールアドレスは会員のログイン ID です。打ち間違えるとログインできなくなります。他人がログインして書き換えれば、アカウントを乗っ取れます。
- **対応の案**：新しいアドレスに確認コードを送り、コードを入力できた人だけが変えられる形にします。確認コードの部品（`MemberVerificationCode`）は、会員登録とログインで使っているものがあります。
- **対応した内容**：プロフィールの保存でメールアドレスが変わるときだけ、新しいアドレスに確認コードを送り、コードが入力できた時点で保存します（`EmailChange`。利用ガイド14章）。個人会員のマイページと、企業会員の担当者の「自分の情報の変更」が対象です。企業会員でほかの担当者が変える画面と、管理画面は、変える人が新しいアドレスのメールを受け取れないので、今までどおりです。

### 2. 外部から読み込むファイルの改ざん対策（SRI）

- **今の状態**：Bootstrap と jQuery を CDN（`cdn.jsdelivr.net`）から読んでいます。中身が正しいかを確かめる指定（`integrity` 属性）は付けていません（`layouts/app.blade.php`・`layouts/admin.blade.php`）。
- **なぜ要るか**：CDN の側のファイルが書き換えられると、全部の画面で他人のプログラムが動きます。近年、実際に起きている攻撃です。
- **対応の案**：`<link>` と `<script>` のタグに、`integrity` と `crossorigin` の属性を足します。版を上げるときは、値も付け直します。
- **対応した内容**：CDN から読み込む Bootstrap・jQuery・summernote の `<link>` と `<script>` に、`integrity` と `crossorigin` を付けました（`layouts/` の3つ、`admin/news/create.blade.php`・`edit.blade.php`、`company/users/index.blade.php`）。Cloudflare Turnstile は、Cloudflare が中身を随時更新するので付けていません。

### 3. セキュリティのヘッダー

- **今の状態**：付けていません。
- **なぜ要るか**：ほかのサイトの中に画面を埋め込まれて操作させられる攻撃（クリックジャッキング）などを防ぎます。審査や脆弱性診断で、まず指摘される所です。
- **対応の案**：全部の応答に、次のヘッダーを付けるミドルウェアを足します。
  - `X-Frame-Options`（ほかのサイトへの埋め込みを断る）
  - `X-Content-Type-Options`（ファイルの種類の決めつけを断る）
  - `Referrer-Policy`（移動先に渡す URL を絞る）
  - `Strict-Transport-Security`（HTTPS だけで開かせる。本番だけ）
  - `Content-Security-Policy`（読み込んでよい場所を決める）。画面の中に書いたスクリプトや、CDN・Cloudflare Turnstile・郵便番号の検索があるので、最初は報告だけのモードで始めて、止まるものが無いことを確かめてから有効にします。
- **対応した内容**：`Content-Security-Policy` のほかの4つを、全部の応答に付けました（`SecurityHeaders`。利用ガイド0章）。`Strict-Transport-Security` は、HTTPS で届いたときだけ付きます。Apache が直接返すファイル（`public/build/`・`public/storage/`）には付かないので、そちらは Apache の設定で付けます。

### 4. 一斉メールの配信停止

- **今の状態**：仕組みがありません。宛先は、送るたびに CSV で渡します。
- **なぜ要るか**：特定電子メール法は、広告のメールに配信停止の方法を載せることを求めています。Gmail なども、大量に送る相手に、ワンクリックで解除できること（`List-Unsubscribe` ヘッダー）を求めています。
- **要るかどうか**：送る内容が広告にあたるなら必須です。事務的な連絡だけなら、要りません。
- **対応の案**：配信停止のアドレスを持つテーブルを作り、本文の末尾とヘッダーに解除のリンクを入れます。送るときに、配信停止のアドレスを宛先から外します。

### 5. お問い合わせの保存期間

- **今の状態**：お問い合わせ（`t_inquiries`）と添付ファイルを消す仕組みがありません。
- **なぜ要るか**：個人情報は、要らなくなったら消すのが原則です。
- **対応の案**：残す日数を `.env` で決め、過ぎた行と添付ファイルを、一時データの後片付け（`TemporaryDataCleaner`）で消します。操作ログ（`OPERATION_LOG_DAYS`）と同じ形です。日数は、サイトの運用で決めます。

## 余裕があれば対応したいもの

### 6. 管理画面の無操作でのログアウト

- **今の状態**：セッションの期限（`SESSION_LIFETIME`。既定は120分）だけです。管理画面と会員の側で、同じ値です。
- **なぜ要るか**：席を離れたままの端末を守ります。
- **対応の案**：管理画面だけ、短い時間（たとえば30分）操作が無ければログアウトさせます。

### 7. 管理画面の接続元の制限

- **今の状態**：どこからでも、ログイン画面を開けます。
- **なぜ要るか**：事務所などの決まった場所からしか使わないなら、ほかからは入口も見せないほうが安全です。
- **対応の案**：`.env` に、入ってよい IP アドレスを書きます。空なら制限しません。サーバーの前にプロキシを置くときは、`TRUSTED_PROXIES` の設定が先に要ります（利用ガイド0章）。

### 8. 新しい端末からのログインのお知らせ

- **今の状態**：ログインは操作ログに残りますが、本人には知らせていません。
- **なぜ要るか**：乗っ取りに、本人が気付けます。
- **対応の案**：信頼済みでない端末からログインしたときに、本人へメールを送ります。端末の種類（`UserAgentLabel`）と日時を載せます。

### 9. 漏えいしたパスワードの拒否

- **今の状態**：パスワードの決まりは「8文字以上」だけです。
- **なぜ要るか**：よそで漏えいしたパスワードの使い回しが、乗っ取りのいちばん多い原因です。定期的に変えさせるよりも、漏えいしたものを断るのが今の考え方です。
- **対応の案**：Laravel の `Password::min(8)->uncompromised()` を、パスワードを決める所のルールに使います。外部のサービスに、パスワードのハッシュ値の頭の5文字だけを送って照合します。外部へ送る情報が1つ増えるので、利用ガイドの付録の「外部へ送っている情報の表示」にも足します。

### 10. アップロードのウイルス検査

- **今の状態**：種類と大きさは確かめていますが、中身の検査はしていません。
- **なぜ要るか**：お問い合わせの添付ファイルは、スタッフが開きます。
- **対応の案**：サーバーに ClamAV を入れ、アップロードを受け取るとき（`AjaxFileUpload`）に調べます。サーバーの側の準備が要ります。

## プログラムの外で決めること

パッケージの脆弱性の確認、送信元の認証（SPF・DKIM・DMARC）、バックアップと戻す手順、外部へ送っている情報の表示は、利用ガイド（`neobit-framework-guide.md`）の付録「フレームワーク外で考慮すべきセキュリティ対策」に移しました。サイトを公開する前に確かめる項目として、そちらにまとめています。
