# 仕様メモ：アップロードの欄の必須（upload-required）

- 実装プロンプト：`docs/prompt/upload-required.md`
- 実装完了日：2026-10-21

> **後続タスクによる変更（2026-10-25 追記）**
> E の「CSV の取り込みには、必須が効かない」は直した。取り込みでも必須の欄を確かめ、必須の欄があるコーナーは CSV で追加できない。詳しくは `docs/child-tables-csv-import-spec.md`。

## A. 概要

**目的・解決する課題**

アップロードの欄（`UPLOAD_FILES`）を、`'required' => true` で必須にできるようにした。今までは書き方が無く、`rules()` に `required` を書くと、`+` で足しているアップロードの hidden のルールが消えるうえ、新しく選んだだけのときは欄の値が空で届くので、正しく判定できなかった。

見本は、ニュースの一覧用画像。

**影響範囲**

| 範囲 | 内容 |
|---|---|
| フレームワーク | `UPLOAD_FILES` に `required` を足し、FormFlow の検証で必須のルールを足す。アップロードの部品が、自分の欄のエラーの欄を出す |
| 見本のサイト | ニュースの一覧用画像を必須にし、見出しに必須マークを付けた |
| 既存のデータ | 一覧用画像の無いニュース（シーダーで作ったものなど）は、編集して保存するときに画像を選ぶ必要がある |

## B. 実装仕様

**書き方**

```php
private const UPLOAD_FILES = [
    'list_image' => ['type' => UploadType::Image, 'width' => News::LIST_IMAGE_WIDTH, 'required' => true],
];
```

- `'required'` は省略できる（false）。true・false でなければ `LogicException`。
- 定義の形（`UploadFieldDefinitions::of()`）に `required` を足した。`upload_field()` の項目にも `required` を足した。

**判定**（`Neobit\Core\Rules\UploadRequiredRule`）

| ファイルがあるとみなすとき | 中身 |
|---|---|
| 新しいファイル | `_tmp` の名前が `SAFE_FILENAME` の形で、一時ディレクトリにそのファイルが今ある |
| 今のファイル | 欄の値が、レコードの今の値と一致し、`_del` が立っていない。新規登録や新しい行では、今のファイルは無い |

- 値が空でも呼ばれるルール（`$implicit = true`）。新しく選んだだけのときは、欄の値が空で届くため。
- エラーは `validation.required` を訳した文（今の日本語は「この項目は必須です。」）。lang の置き換えがそのまま効く。

**ルールの付け方**

- FormFlow の `validatedInput()` が、`rules($record)` の結果に足す。キーが同じなら、今のルールの後ろに足す（ファイル名の形を確かめるルールは残る）。
- 1つだけの欄：`AjaxFileUpload::requiredUploadRules($record)`。キーは欄の名前（`list_image`）。
- 組の中の欄：`ChildTables::childTableRequiredRules($request, $record)`。空の行を除いた後の行ごとに、キーは `photos_image.0` の形。行の今のファイルは、保存のときと同じ見分け方（この親の行の id で、同じ id の2回目ではないもの）で決める。
- 「少なくとも1つ」は書き方を足さない。ファイルだけの組では、組の `'min' => 1` で決まる。

**画面**

- `requiredFields()` が、`requiredUploadFields()`（必須の欄の名前。組の中の欄も入る）にも必須マークを付ける。
- `_ajax_upload_block` が、入力の画面で枠の下に `<div class="invalid-feedback mb-2" data-item="欄の名前">` を出す。組の中の欄の `data-item` は `photos_image.0` の形。
- ニュースの入力欄（`admin/news/_fields.blade.php`）の一覧用画像の見出しに、`{!! $required['list_image'] ?? '' !!}` を付けた。

## C. 前提・依存

- FormFlow の `validatedInput()`（確認画面へ進むときと、保存のときの両方が通る）
- AjaxFileUpload・UploadFieldDefinitions・UploadFilePath（一時ディレクトリと、ファイル名の形）
- 子テーブル（空の行の除き方と、行の見分け方）
- 画面のエラーの表示（`global.js` が `invalid-feedback[data-item]` に入れる）

## D. 設計判断とトレードオフ

| 判断 | 採用 | 不採用とその理由 |
|---|---|---|
| 書く場所 | `UPLOAD_FILES` の `'required' => true` | `rules()` に書かせる：hidden のルールが消え、4本の hidden を組み合わせた判定を、コーナーごとに書くことになる |
| 今のファイルの判定 | レコードの今の値と照らす | hidden の値を信じる：書き換えた hidden で必須をすり抜けられる |
| 新しいファイルの判定 | 一時ファイルが今あるかまで見る | 名前があればよい：片付けで消えた一時ファイルの名前でも通り、ファイルの無いまま保存される |
| ルールを足す場所 | FormFlow の `validatedInput()` | `ajaxUploadRules()` に入れる：コントローラーの `rules()` はレコードを受け取らないことがあり、今の値と照らせない |
| エラーの文 | `validation.required` | 「〇〇を選んでください。」：通常の項目と文が揃わず、lang の置き換えも効かない |
| エラーの欄 | `_ajax_upload_block` が出す | 画面ごとに書かせる：欄の部品が欄のマークアップを持っているので、書き忘れが起きやすい ※今の画面には、アップロードの欄の `invalid-feedback` がどこにも無いので、二重には出ない |

## E. 課題・懸念点

| 重要度 | 内容 |
|---|---|
| 中 | CSV の取り込みには、必須が効かない（取り込みは `validatedInput()` を通らない）。ニュースの CSV で、一覧用画像の無い記事を登録できる |
| 低 | 一覧用画像の無い既存のニュースは、編集して保存するときに画像を選ぶ必要がある |
| 低 | 組の行のひな型の中のエラーの欄は `data-item` が `photos_image.0` になる（キャプションの欄と同じ作り）。行を足した後に検証で戻ると、エラーは行の番号の欄に出る |

## F. セキュリティ・権限・データ整合性の注意

- 今のファイルは、編集しているレコードの今の値と照らすので、hidden の書き換えでは必須をすり抜けられない。ほかの記事のファイル名を送っても断る（テストで確かめた）。
- 一時ファイルの名前は、`SAFE_FILENAME` の形を確かめてから、一時ディレクトリにあるかを見る。パスを含む名前では探さない。
- 確認画面を通さずに保存を送られても、同じ検証で断る。

**実施済み**

- `tests/Feature/UploadRequiredTest.php`（6件）
  - 一覧用画像が無いと確認画面へ進めず、`list_image` に「この項目は必須です。」が出る
  - 一時ファイルがあれば通り、名前だけでファイルが無ければ断る
  - 今のファイルを残せば通り、削除の印を立てるか、ほかの記事のファイル名に書き換えると断る

  - 新規登録の画面に、必須マークとエラーの欄が出る
  - 組の中の欄（テスト用のコントローラー）：今のファイルを残した行と新しいファイルの行は通り、画像の無い行だけが行ごとにエラーになる。新規登録では、ファイル名だけを送っても断る
