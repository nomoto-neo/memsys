# 仕様メモ：slug の検証のルール（slug-rules）

- 実装プロンプト：`docs/prompt/slug-rules.md`
- 実装完了日：2026-10-26
- 計画書の段階4-9（SEO）の3

## A. 概要

**目的・解決する課題**

固定ページだけが持っていた slug（URL の名前）の検証を、どのコーナーでも使えるフレームワークの検証のルール（`SlugRule`・`NotReservedPathRule`）にした。slug の列はコーナーのテーブルに持ったまま、検証のルールだけを共通にした（計画書のとおり。重なりの検証は `Rule::unique`、URL から探すのは `where()`、入力の欄は文字の入力1つで足りるので、部品にしない）。

**影響範囲**

| 範囲 | 内容 |
|---|---|
| フレームワーク | 検証のルール2つを足した |
| 見本のサイト | 固定ページの `Page::SLUG_PATTERN` と `Page::isReservedSlug()` を外し、管理画面の検証と訪問者の側のルートを、新しいルールに乗せ替えた |
| 動き | 変わらない（固定ページのテストがそのまま通る） |

## B. 実装仕様

**`Neobit\Core\Rules\SlugRule`**

- 定数 `PATTERN`（`[a-z0-9][a-z0-9_-]*`）と `NESTED_PATTERN`（`PATTERN` を「/」でつないだもの）。
- `new SlugRule(nested: true)` なら `NESTED_PATTERN`、無ければ `PATTERN` で、値全体を確かめる。合わなければ `validation.regex` の文（「この項目の形式が正しくありません。」）。
- 訪問者の側のルートの `where()` にも同じ定数を使う。

**`Neobit\Core\Rules\NotReservedPathRule`**

- 名前の最初の区切りが、ほかのルートの URL の最初の区切りと同じなら断る（「この名前は、ほかの画面のURLで使っているので使えません。」）。
- `isReserved()`（静的）で、検証の外からも確かめられる。URL の直下のルート自身（`/{slug}`）は、最初の区切りが変数なので重ならない。
- URL の直下に置くコーナーだけが使う。

**見本のサイト**

- `Admin\PageController::rules()` の slug：`new SlugRule(nested: true)`・`Rule::unique(...)`・`new NotReservedPathRule()`。
- `routes/web.php` の固定ページのルート：`->where('slug', SlugRule::NESTED_PATTERN)`。

## C. 前提・依存

- Laravel の検証（`ValidationRule`）とルートの一覧（`Route::getRoutes()`）
- 固定ページのルートを `routes/web.php` のいちばん最後に置く決まり（今のまま）

## D. 設計判断とトレードオフ

| 判断 | 採用 | 不採用とその理由 |
|---|---|---|
| 共通にする範囲 | 形と、ほかの画面と重ならないことの検証のルールだけ | 入力の欄・URL から探す処理・重なりの検証も部品にする：どれも1行で足り、部品にすると覚えることが増える |
| 「/」でつなぐか | 引数（`nested`）で選ぶ | いつも通す：ニュースのように1区切りでよいコーナーで、「/」入りの名前が入る |
| 形のエラーの文 | 通常の `validation.regex` | 独自の文：lang の置き換えが効かない |
| ほかの画面と重ならないルールを分けるか | 分ける | 形のルールに含める：頭の付いた URL に置くコーナーでは要らない |

## E. 課題・懸念点

| 重要度 | 内容 |
|---|---|
| 低 | 後から足した画面の URL が、すでにあるページの名前と重なったときは、画面のほうが先に当たり、ページは開けない（今までと同じ。利用ガイドに書いてある） |

## F. セキュリティ・権限・データ整合性の注意

- slug の形は、英小文字・数字・ハイフン・アンダーバーと「/」だけ。パスをさかのぼる「..」や、空白・記号は入らない。
