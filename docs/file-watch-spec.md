# 仕様メモ：改ざん監視（file-watch）

- 実装プロンプト：`docs/prompt/file-watch.md`・`docs/prompt/file-watch-accept.md`（手で認める取り込み）
- 実装完了日：2026-10-27（手で認める取り込みは 2026-10-29）
- 計画書の段階4-11

## A. 概要

**目的・解決する課題**

このフレームワークは、サイトの運営者が自分で守る機能（IPブロック・操作ログ・怪しい操作やエラーの通知）を持つことを主な目的にしている。改ざん監視は、入口で止めきれずにファイルを書き換えられたときに、侵入者が仕組みに気付く前に知らせる。通常の運用では変わらないファイルの変化と、アップロードの置き場所に置かれた動くファイルを、通知のメールで知らせる。

**影響範囲**

| 範囲 | 内容 |
|---|---|
| フレームワーク | `FileWatcher`（判断と記録）、コマンド `app:watch-files`（`--init`・`--full`・`--accept`）、メールのテンプレート `file_watch_alert`、設定の `file_watch`、1日1回の操作ログの報告に「ファイルの更新」 |
| 見本のサイト | 鍵のファイル `.version` |
| サーバー | コードを更新する利用者の crontab に2行、`--init` を1回 |

## B. 実装仕様

**記録**（`bootstrap/cache/file-watch.json`。コードを更新する利用者だけが書け、apache は読むだけ）

| キー | 中身 |
|---|---|
| `files` | 基準。名前 => ctime・大きさ・sha256 |
| `keys` | 気付いた鍵の ctime。2日分 |
| `deleted_seen` | 消えたファイルに最初に気付いた時刻 |
| `accepted` | 通常の更新の記録。期間（最初の鍵・始め・終わり）とファイルの名前。手で認めた更新は `manual: true` と認めた時刻（始め・終わりとも）とファイルの名前。8日分 |
| `last_alert` | 最後に知らせた顔ぶれのハッシュ値と時刻 |

**監視する場所**

- `basePath` の下：`app`・`packages`・`config`・`routes`・`bootstrap`・`database`・`resources`・`lang`・`code`。`--full` のときは `vendor` も。
- `bootstrap/cache` の設定などのキャッシュ（`config.php` など）も見る。この監視の記録とロックのファイル（`file-watch.json`・`.tmp`・`file-watch.lock`）は外す。
- プロジェクトの直下の全部のファイル（`.env` を含む）。中身まで見る。鍵のファイルと `.phpunit.cache`・`.phpunit.result.cache` は外す。
- プロジェクトの直下のディレクトリは、名前の一覧（記録の `root_dirs`）と比べ、増えた・消えたことだけを見る。名前は末尾に `/` を付ける。前の版の基準に一覧が無ければ、最初の回で知らせずに作る。
- 公開ディレクトリ（`public_path()`）の下。`storage`（アップロードへのリンク）と `hot` を除く。名前は `public/…`。
- シンボリックリンクはたどらない。

**1回分の流れ**（`FileWatcher::check()`）

1. 鍵のファイルの ctime が新しければ、履歴に足す
2. 鍵の履歴から、更新の期間を作る（鍵どうしの間が30分以内なら1つ。期間は最初の鍵の20分前から最後の鍵の15分後まで）
3. 今のファイルを stat し、基準と比べる。ctime か大きさが違うもの（`--full` なら全部）だけ sha256 を取り直し、同じなら基準の ctime と大きさだけを新しくする
4. 変わった・増えた・消えたファイルを、ctime（消えたものは最初に気付いた時刻）で判断する
   - 期間に入る：通常の更新。基準に取り込み、期間の記録に足す
   - 期間に入らず、15分たっていない：待つ
   - それ以外：知らせる。基準には取り込まない
5. 公開のアップロードの置き場所（`storage/app/public`）の、許可されていないアップロードファイルを探す。PHP として動く拡張子と、アップロードの設定（`upload.image_types`・`attach_types`）と `file_watch.public_upload_extra` に無い拡張子のもの（Laravel の `.gitignore` を除く）。非公開の置き場所（`storage/app/private`）は見ない
6. 知らせるもの（改ざんの疑い・許可されていないアップロードファイル・開けなかったディレクトリ）があれば、顔ぶれが変わったとき、同じなら1時間ごとに、通知のメールを送る

- アップロードの置き場所の `.htaccess`・`.user.ini` は、5 の確かめには入れず、3・4 でほかのコードと同じく基準と比べる。プラグインなどが置く正しいものもあり、すぐ知らせ続けると止められないため（2026-10-29 に変えた）。記録の `upload_config` が無い前の版の基準では、最初の回だけ、今あるものを知らせずに基準に取り込む。
- 開けないディレクトリは、止まらずに飛ばし、「確かめられなかったディレクトリ」として知らせる。その下のファイルは、消えたものにしない。
- 記録の隣のロックのファイル（`bootstrap/cache/file-watch.lock`）を `flock` で押さえ、前の回が動いている間は、次の回は何もせずに終わる。

**コマンド**（`app:watch-files`）

- `file_watch.release_file` が空なら、何もしない。
- `--init`：今の状態（`vendor` を含む）を基準にする。
- `--accept`：その場で確かめ直し（`vendor` は見ない）、そのとき知らせるファイル（変わった・増えた・消えたファイルと、直下のディレクトリの増減）の一覧を出して、確認してから基準に取り込む（`FileWatcher::acceptAlerts()`）。
  - 待っている最中の変化・許可されていないアップロードファイル・開けなかったディレクトリは取り込まない。
  - 取り込んだら、`accepted` に手で認めた更新として足し、通知の控え（`last_alert`）を消し、info のログに名前を残す。
  - 断ったときと、知らせるものが無いときは、疑いを取り込まず、通知の控えも変えない。期間に入る通常の更新は、どちらでもいつもどおり取り込む。
  - 確かめて分ける処理（`sort()`）は `check()` と同じものを使う。
- 基準が無ければ、`--init` を案内して止まり、warning のログに残す。
- 宛先は `file_watch.to`、無ければ `ERROR_NOTIFY_TO`。宛先が無いときと送れなかったときは、critical のログに残す。

**通知のメール**（`file_watch_alert`）

- 件名：`【緊急：サイト名】ファイルの改ざんを検知しました（変更 N件・追加 N件・削除 N件）`
- 本文：許可されていないアップロードファイル、変わった・増えた・消えたファイル（名前と時刻）。

**1日1回の報告**（`OperationLogReport`・`app:report-operation-logs`）

- `file_updates`：その日にかかる通常の更新の期間ごとに、「2026-10-27 14:00〜14:40 の更新（12件）」とファイルの名前（10件まで、多いときは「ほか○件」）。手で認めた更新は「2026-10-29 16:40 に手で認めた更新（3件）」の見出しで並べる。
- 一覧のある日は、気になる点が無くても送る。

## C. 前提・依存

- サーバーの権限の形：コードを更新する利用者と、PHP-FPM・cron の apache が別。`bootstrap/cache` は apache が読めて書けない
- 改ざん監視の cron は、コードを更新する利用者の crontab で動かす
- エラーの通知（20章）・操作ログの報告（22章）

## D. 設計判断とトレードオフ

| 判断 | 採用 | 不採用とその理由 |
|---|---|---|
| 知らせ方 | 通知のメールだけ | 管理画面に出す：改ざんされたら管理画面を見て運用する状況ではない |
| 動かす権限 | コードを更新する利用者の crontab | Laravel のスケジューラー（apache）：記録を apache が書けると、攻撃者も書ける |
| 記録の置き場所 | `bootstrap/cache` | `storage`：apache が書ける |
| 時刻 | ctime | mtime：`touch -d` で書き換えられる |
| 通常の更新の見分け方 | 鍵のファイルの前後の期間に入るか（ファイルごと、ctime で） | 監視の回った時刻で判断する：続けて更新すると、どこからどこまでが1回の更新か分からない |
| 期間の前の余白 | 20分（15分＋監視の間隔） | 15分：鍵が監視の1回の間に2度更新されると、前の更新の分を取りこぼす |
| 鍵が後から届くとき | 15分待ってから知らせる | 送る手順の最初に鍵を送ると決める：手で送る運用では送る順番を守りにくい |
| 知らせ続けるか | 直るまで、1時間に1回 | 1回だけ：知らせが止まると直ったと思われる |
| 鍵のファイルの名前 | 設定（案件ごと）。既定 `.version` | `.env`：環境ごとではなく案件ごとに決めるもの |
| 公開のアップロードの置き場所の確かめ | アップロードの設定に無い拡張子は全部知らせる | 危ない拡張子を並べる：JavaScript・HTML・SVG などの書き漏れが出る |
| アップロードの置き場所の確かめる範囲 | 公開の置き場所（`storage/app/public`）だけ | `storage/app` の全部：非公開のファイルは apache しか読めない権限（0700）で作られ、監視の利用者には開けず止まる（開発サーバーで実際に止まった）。Web から開けないので、置かれても動かせない |
| 直下のファイル | 全部を中身まで見る（`.env` を含む） | 名前の一覧だけ：`.env` の書き換えに気付けない |
| 直下のディレクトリ | 名前が増えた・消えたことだけ | 中身まで見る：`tests/`・`docs/` などはサイトの更新でよく変わり、鍵の送り忘れの誤った知らせが増える |
| `bootstrap/cache` | 設定などのキャッシュを見る | 外す：サーバーの Laravel が実際に読むのはここで、書き換えられるとすぐ効く |
| Laravel が動かなくなる改ざん | cron の `MAILTO` で、コマンドのエラーの出力を送る | 何もしない：監視も止まり、気付けない |
| 開けないディレクトリ | 飛ばして知らせる | 止まる：監視全体が動かなくなる。黙って飛ばす：改ざんを隠す場所になる |
| 同時に動かない | ロックのファイル（`flock`） | 時刻をずらすだけ：`--full` が長くかかると、次の回と重なる |
| 鍵を送り忘れた更新の解消 | `--accept` で、そのとき知らせるファイルだけを確認して取り込み、記録に残す | `--init` だけ：待っている最中の変化まで黙って取り込み、通常の更新の記録も消える。後から鍵だけを送る：消えたファイルは時刻が変わらず、期間に入らない |
| `--accept` の確認 | 一覧を出して毎回聞く。聞かずに進むオプションは無い | 聞かずに取り込む：手で動かすだけのコマンドで、確かめずに取り込む使い方を許さない |

## E. 課題・懸念点

| 重要度 | 内容 |
|---|---|
| 中 | サーバーそのもの（root）を乗っ取られたら信用できない。外部の監視サービスと組み合わせる |
| 中 | 共用のサーバーで、Web とファイルの更新が同じ利用者のときは、記録を守れない |
| 中 | Laravel が動かなくなる改ざんでは、監視も止まる。cron の `MAILTO` で、コマンドのエラーの出力が届くようにする（PHP や cron そのものを止められたら届かない） |
| 低 | 知らせるまで最大でおよそ20分かかる |
| 低 | DB の中身は見ない |
| 低 | 鍵を送り忘れた更新は、さかのぼって通常の更新にならない。中身を確かめて `--accept` で取り込む |
| 低 | サーバーでの動作（crontab・権限・ctime）は、まだ確かめていない |

## F. セキュリティ・権限・データ整合性の注意

- 記録はコードを更新する利用者だけが書け、Web の側（apache）からは読むことしかできない。管理画面から基準を作り直す仕組みは作らない。
- 鍵のファイルも、コードを更新する利用者だけが書ける場所に置く。
- 通常の更新とみなしたものも、1日1回の報告で運営者の目に入る。

## G. テスト状況

**実施済み**（`tests/Feature/FileWatchTest.php`、一時のディレクトリで、ctime はテストが決める）

- 何も変わらなければ何も出ない
- 鍵の無い変化は15分待ってから知らせ、同じ顔ぶれは1時間に1回、元の中身に戻れば知らせない
- 鍵の前後の変化は通常の更新になり、報告の記録に期間ごとに載る。期間の外の変化は知らせる
- 2分おきに20回続けて更新しても（見えない鍵があっても）、1つの期間になり、何も知らせない
- 見えなかった最初の鍵の15分前のファイルも、前の余白（20分）で受ける
- 消えたファイルは、最初に気付いた時刻から15分待って知らせる
- 公開のアップロードの置き場所では、`.php`・JavaScript・HTML・SVG をすぐ知らせ、画像・PDF・`.gitignore` は知らせない。設定に足した拡張子は知らせない。非公開の置き場所は見ない
- アップロードの置き場所（`storage/app/public` と WordPress の `upload_path`）の `.htaccess` は、鍵と一緒なら通常の更新、鍵の無い追加と書き換えは15分待ってから改ざんとして知らせ、すぐ知らせる危ないファイルにはしない。前の版の基準からは、最初の回だけ知らせずに取り込む
- 前の回がロックを押さえている間は、次の回はロックを押さえられない
- `bootstrap/cache/config.php` の書き換えを知らせ、この監視の記録は知らせない
- 直下の `.env` の書き換えと、知らないファイルを知らせる。記録に `.env` の中身が残らない
- 直下に増えたディレクトリを、鍵が無ければ知らせ、鍵の前後なら通常の更新にする。鍵のファイルとテストでできるものは知らせない
- 前の版の基準（直下の一覧が無いもの）で動いても、知らせずに一覧を作る
- 開けないディレクトリは止まらずに知らせ、その下を消えたものにしない（root 以外の Linux でだけ動くテストで、手元の Windows では飛ばす）
- `bootstrap/cache` は見ず、`vendor` は `--full` のときだけ見る
- 鍵の設定が空なら何もせず、基準が無ければ `--init` を案内して止まる
- 手で認めると、知らせていた書き換えと削除だけを取り込み、待っている変化と危ないアップロードは残る。認めたものは手で認めた更新として記録に載る
- 断ったら何も取り込まず、通知の控えもそのまま。知らせるものが無ければ聞かない
- `--accept` は一覧を変更・追加・削除の順に出し、確認してから取り込む

1日1回の報告での「手で認めた更新」の見出しは、テストしていない（報告は実際のプロジェクトの記録を読むため）。
