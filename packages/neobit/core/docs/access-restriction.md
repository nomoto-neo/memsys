# アクセス制限（接続元の IP アドレスの制限）

<p align="right"><a href="../guide.md">利用ガイドへ戻る</a></p>

**ファイル**：`packages/neobit/core/src/Security/AccessRestriction.php`（冒頭のコメント）・`src/Http/Middleware/RestrictSiteAccess.php`・`RestrictAdminAccess.php`・`src/Http/Controllers/AccessRestrictionController.php`、画面は `packages/neobit/core/resources/views/maintenance.blade.php`

サイト（訪問者画面）と管理画面を開ける IP アドレスを、管理画面の「アクセス制限」で、それぞれ絞れます。運用する人が、サーバーに入らずに変えられます。管理画面の制限はサイトに掛からず、サイトの制限は管理画面に掛かりません。管理画面の IP アドレスは、サイトの制限でも通します（下の「管理画面に入れる人」）。

画面は、上から次の順に1つの枠に並べています。

| 画面の項目 | 働き | 使うとき |
|---|---|---|
| メンテナンス画面を表示する（チェック） | 下の2つの IP アドレスのほかに、メンテナンス中の画面を 503 で返す。管理画面には掛からない | 公開前のデモの運用、メンテナンスの間 |
| メンテナンス中も訪問者画面を閲覧できるIPアドレス | サイト（訪問者画面）の許す IP アドレス | |
| 常にサイト全体を閲覧できるIPアドレス | 管理画面の許す IP アドレス。メンテナンス中の訪問者画面も開ける | |
| 管理画面の存在を隠す（チェック） | 「常にサイト全体を閲覧できるIPアドレス」のほかに、ログイン画面も含めて 404 を返す。訪問者画面には掛からない | 事務所などの決まった場所からしか管理画面を使わないサイト |

- **入力**：1行に1つです。`#` から後ろはコメントで、IP アドレスとの間の空白はあってもなくてもかまいません（`203.0.113.10  # 事務所`・`203.0.113.10#事務所`）。行の頭に `#` を付けると、その行は使いません。どの IP アドレスが誰のものかを残せ、一時的に外すときも `#` を付けるだけで済みます。カンマでは区切れません（コメントの中のカンマと取り違えないため）。`192.168.0.0/24` のようなまとまりと、IPv6 も書けます。
- **保存の形**：入力した文を、コメントも並び順もそのまま保存し、画面にもそのまま出します。判断に使う IP アドレスの一覧は、保存のときにそこから作ります。コメントを書けるようになる前に保存した設定は、一覧を1行1つにして出します。
- **チェックを入れたときだけ掛かる**：IP アドレスを書いただけでは、制限は掛かりません。
- **管理画面に入れる人**：管理画面の IP アドレス（画面と `.env` の `ADMIN_ALLOWED_IPS`）は、サイトの制限でも通します。管理画面に入れる人が、メンテナンス中のサイトを確かめたり、WordPress のブロックエディタで記事を保存したり（[wordpress.md](wordpress.md)）できるようにするためです。管理画面の制限のチェックが無くても、一覧に書いた IP アドレスは通ります。一覧が空なら、サイトの制限が全員に開くことはありません。
- **設定ファイルの分**：`.env` の `SITE_ALLOWED_IPS`・`ADMIN_ALLOWED_IPS` に書いた IP アドレスは、それぞれの一覧に足し合わせます。画面からは外せず、画面にはそれぞれの欄の下に「次のIPアドレスは、設定ファイルにより常に許可されています。」と出ます。サーバーを管理する人の事務所などを書いておくと、画面でどう設定しても締め出されません。`.env` を変えたら `php artisan config:cache` をやり直します。
- **締め出さない**：管理画面の制限を掛けて保存するとき、今の自分の IP アドレスが管理画面の一覧に無ければ、保存させません。サイトの制限は管理画面に影響しないので、確かめません。それでも回線が変わるなどで締め出されたときは、サーバーで `php artisan neobit:access-denied-off` を実行します。両方の制限を外します。IP アドレスの一覧は残ります。
- **ルート**：案件が書きます。機能を使うかどうかを、案件ごとに決めるためです。管理者だけのグループの中に、`Neobit\Core\Routing\FrameworkRoutes` の1行を書きます。

    ```php
    // routes/admin.php（管理者だけのグループの中）
    FrameworkRoutes::accessRestriction('/access-restriction');
    ```

- **サイトの制限から管理画面を外す**：管理画面（設定の `route.admin_path` の下）は、いつもサイトの制限の外です（`RestrictSiteAccess` が足します）。`bootstrap/app.php` に書く必要はありません。
- **設定の置き場所**：DB の `settings` テーブルです。毎回のアクセスで読むので、キャッシュに置き、保存のたびに作り直します。変えた内容は、使う IP アドレスとコメント（`203.0.113.10（事務所）` の形）を並べて、操作ログに「アクセス制限の変更」として残ります。
- **IPブロック管理との関係**：2つの一覧にある IP アドレスは、IPブロック管理で止めません（[ip-block.md](ip-block.md)）。
- **入口の見張り**：アクセス制限も、IPブロック管理と同じく、Laravel を起動する前の見張りが先に判断します（[ip-block.md](ip-block.md)の「入口の見張り」）。メンテナンス中の画面を変えたとき（`resources/views/vendor/neobit/maintenance.blade.php`）は、`php artisan neobit:gatekeeper --export` で見張りの画面も作り直します。
- **プロキシを前に置くときは、`TRUSTED_PROXIES` を先に書きます**。書かないと、全員がプロキシの IP アドレスに見えるので、全員が通るか、全員が止まります。
- **メンテナンス中の画面**は、レイアウトを継承しない1枚の HTML です。DB もセッションも使わないので、DB を止めている間も出せます。文言は、アプリの `resources/views/vendor/neobit/maintenance.blade.php` に同じ名前で置いて上書きします。デモの運用のときも、この画面が出ます。
- **503 で返す**のは、一時的に止めていることを検索エンジンに伝えて、登録を消されないようにするためです。
- **制限の間も通すパス**は、`bootstrap/app.php` の `RestrictSiteAccess::except()` に書きます。今は、死活監視（`/up`）と、お知らせメールの配信停止（`/mail/unsubscribe`）です。止めている間に届いたメールからも、停止できるようにするためです。管理画面（設定の `route.admin_path` の下）は、書かなくてもいつも通します。
- **管理画面を 404 にする**のは、そこに管理画面があることを知らせないためです。止めたアクセスは、操作ログに残しません。
- **Apache が直接返すファイルは止まりません**。`public/build/` の中と、公開のアップロードファイル（`public/storage/`）は、Laravel を通らないためです。そこまで止めるときは、Apache の設定で絞ります。
- **コマンドは止まりません**。スケジューラー（[scheduler.md](scheduler.md)）とキュー（[queue.md](queue.md)）は、制限の間も動きます。メンテナンスの間に一斉メールを送りたくないときは、送信が終わってから止めます。
- Laravel の `php artisan down` は使いません。サーバーでコマンドを打つ必要があり、画面の設定とは別の仕組みになるためです。
